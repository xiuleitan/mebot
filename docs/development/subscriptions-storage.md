# 订阅本地存储基础

> 2026-10-28 界面简化：移除账单入口、归档操作、变更记录浏览及独立提醒设置。详情改为基本字段、账号下方备注与一行“聊天／编辑／删除”。取消续费通过聊天或编辑保存，显示“已取消续费”；到期按日期派生，不再写自动归档。既有表、历史快照、流水、图片和交付回执保留，未改数据库版本或持久格式。下文的阶段实现记录描述数据能力；当前用户界面以 [订阅主界面](../design/subscriptions-ui.md) 为准。

第 1、2 阶段已将订阅存储注册到应用主库 schema 15，并接入真实本地管理。第 3 阶段增加账务与首页统计；第 4、5 阶段按用户最新要求改为仅通过聊天创建，接入文字／截图提取、追问及会话内确认。沿用已安装的表结构、索引和 identity，不改变 schema 15 或历史迁移。14→15 的协调记录位于共享 Git 元数据的 `mebot-integration/migrations/subscriptions-storage.json`；本分支不执行 main 合并或其他分支回流。

所有结构化记录使用同一个 `mebot.db`，图片复用 `LocalMediaStore` 的持久文件。`AppContainer` 从同一主库建立数据接口，订阅 ViewModel 内组合账务和聊天控制器，无需改公共导航或模型设置。卡片与详情读取真实数据，已有记录可在详情编辑名称、费用、币种、周期、日期、账号、支付方式、备注和图片；新建只从聊天进入。首页统计已接入，第 6 阶段已接入独立提醒引擎、调度和通知详情跳转。

## 数据表

| 表 | 内容与约束 |
| --- | --- |
| `subscriptions` | 标题、账号、支付渠道、定点金额、币种、周期单位及间隔、日期锚点、月末锚点、预计扣费日、有效期、自动续费标记、状态、封面、时间和版本。当前记录是业务状态依据。 |
| `subscription_conversations` | 会话与可为空的订阅绑定。订阅绑定唯一；只允许从未绑定状态建立绑定，不提供切换到另一订阅的接口。 |
| `subscription_drafts` | 每会话独立的未发送输入、待确认字段 JSON、格式版本和乐观版本。正式订阅不依赖这份 JSON。 |
| `subscription_messages` | 用户与助手消息、时间及会话内唯一顺序。按需分页读取，不跨会话拼接。 |
| `subscription_operations` | 请求 ID、来源会话及消息、目标订阅、操作类型、待确认或执行状态、规范化请求、期望版本和执行结果。来源消息通过复合外键约束到同一会话。 |
| `subscription_changes` | 每次写入的前后快照、发生时间、操作 ID 和前后版本。订阅版本、操作 ID 均唯一；历史封面另有外键引用，防止更换当前图片后清掉原图。 |
| `subscription_payments` | 用户确认的实际扣费日期、当时金额及币种、备注、确认时间和稳定扣费事件 ID。同一订阅同一事件只能登记一次，不从预计日期自动生成流水。 |
| `subscription_conversation_media` | 会话与公共媒体的关联、名称、顺序及待发送状态。相同原图可以跨会话复用文件，关联独立。 |
| `subscription_message_media` | 消息发送时的附件快照，复合外键保证附件与消息属于同一会话。移除未发送图片不能删除已经发出的图片。 |

金额使用 `Long` 保存 ISO 币种最小货币单位，例如 CNY 的 2500 表示 25 元，JPY 的 100 表示 100 日元。不使用浮点数，不为未知币种默认填人民币。日期使用 Room 的 LocalDate 转换器保存为自然日，创建和修改时间保存为毫秒时间戳。

`MIGRATION_14_15` 在 Room 升级事务中调用 `SubscriptionStorageSchema.createTables`，只增加 9 张表及索引，保留旧 36 张表、全部记录和文件。Room 完整校验后更新版本与 identity，迁移代码不改写 `room_master_table`，不清库或降级重建。schema 15 的兼容基线提交为 `f2872938cf3270445098257aad5b9fdc86b6c643`，其父级第 1 阶段提交提供实体与数据接口。首次安装 schema 15 后冻结此结构，后续新增结构须另行协调更高版本。

## 事务与恢复

- 创建时同时提交正式订阅、会话绑定、变更快照和成功操作结果。重复确认返回同一条记录，请求 ID 不能换内容后复用；任一步失败则整笔回滚。
- 修改在事务内检查原版本，更新当前记录并追加快照。并发修改只有一个符合原版本，另一方需要重新读取，不能覆盖新内容。
- 扣费流水保存独立的金额、币种和日期快照。改价、归档及预计日期推进不能改写已经确认的扣费；重复事件由唯一索引拦截。
- 用户显式更正流水时，用原流水的操作 ID 和订阅版本共同校验并发，事务内更新该流水、追加操作前后值及订阅变更记录。保留原流水 ID、周期事件和首次确认时间；请求 ID 重试不再写入，换内容须新请求。撤销确认保留原行和金额，以该行最新操作的 `VOID_PAYMENT` 类型标记失效；重新确认沿用原行，不能绕过同一事件唯一约束。
- 发送消息、绑定本次图片及清空本次输入在一个事务中完成。同一消息重试不能清掉后来输入的草稿或消耗后来选择的图片。
- 新开会话创建新的独立草稿，不清除旧的未完成会话。手动保存的订阅首次进入聊天时创建专属会话，之后复用同一份。
- 图片从来源复制到 `filesDir/media/originals`，不把缓存和临时授权当作长期附件。文件发布、公共媒体元数据及会话关联复用现有原子导入流程；失败后的文件进入可恢复清理队列。
- 手动关闭续费只登记本地状态，明确提醒用户在服务商核对实际续费。有效期含所选当天，结束后转归档；有效期可早于未来首次扣费锚点，例如试用结束后的首次扣费。归档不删除业务、图片和会话。
- 页面“删除订阅”是经范围确认的移出列表，保存 `DELETED` 状态并保留历史，可从“已结束的订阅”恢复；不提供静默物理删除历史或切换会话绑定的入口。
- 自动续费按原始锚点推进日期，区分每月固定日与每月最后一天；闰日、季度、半年和长期未启动均确定性计算，不以日期推进冒充已付款。应用启动、回到前台、订阅页面跨日时维护日期，时区使用当前设备设置；独立系统通知调度已在第 6 阶段接入。
- 手动表单草稿保存原始输入、目标与版本和稳定确认 ID。退出、重开或保存失败继续原输入；版本冲突只在用户明确选择“读取最新记录”后替换表单。保存与关闭过渡衔接，处理中禁止重复提交。手动封面不会自动变成聊天待发送附件。

## 第 3 阶段的流水与统计口径

每个订阅详情提供“扣费流水与计划”，按月查看预计计划和实际流水。从计划登记可关联当前周期；“登记其他扣费”用于额外费用、手动续费或一次性支出，不按日期、金额相同就推定属于某个周期。实际日期不能晚于今天；允许补录往月账单、零元确认和更正币种。首次使用无上月证据时显示“暂无记录”，不会反算历史付款。

- 上月消费只按流水的实际扣费自然日汇总已确认记录，排除已撤销确认的流水。归档和删除的订阅仍参与历史汇总。
- 本月预计总消费覆盖整个自然月。确认流水按实际日期计入；本月的未确认自动扣费计划按当时规则枚举。已确认事件即使提前或延后到别的月份支付，也不再重复计入该周期的预计金额；额外流水单独相加。年费只在扣费月计入，不除以十二。
- 日付、周付、月付、年付及间隔从原始锚点枚举，每次维护推进的 `nextBillingDate` 只是列表游标，不会丢掉本月较早的未确认计划。订阅初始锚点可用于估算早期计划，这些仍是预计，不能充当历史扣费证据。
- 改价、关闭续费、归档与恢复按变更发生的本地自然日截断或接续计划；此前发生的计划保留旧价格。改期通过订阅内连续的 `cycle:<序号>` 关联同一期，跨月改期不重复估算。`manual:<请求ID>` 表示无周期关联的额外支出。付款、更正、撤销均不反向重排已经分配的后续周期身份。
- 不同币种分别汇总，无固定汇率或隐式换算。单笔用最小货币单位 `Long`，汇总用 `BigInteger`，防止多笔大金额溢出。

统计在 IO 侧读取同一 Room 事务快照，历史以 200 行分批读取，只保留计费规则字段和事件关联；不读取聊天与媒体内容。统计结果为可重建数据，不写一份独立金额缓存。当前订阅变化、恢复前台和跨日后重新计算；统计失败可重试，不阻塞本地列表或编辑。

扣费表单原始值保存在所属会话的 `subscription_drafts.fieldsJson.paymentEditors` 中。每个周期、已有流水和额外扣费各用独立键，原聊天输入及 `manualEditor` 保持原样。关闭前落库；确认成功后只清理同一请求的草稿。进程若在成功提交后、清理前结束，操作回执保证不会重复扣费登记。并发冲突保留输入，用户明确读取最新记录后再核对提交。

## 聊天作为唯一创建入口

2026-10-27 用户明确要求与日程一致，只从聊天创建订阅卡片。主界面的手动新增、空状态的手动指引以及旧聊天预览文案已删除；ViewModel 不再提供创建表单入口，现有编辑表单只接受已保存的订阅 ID。既有卡片、历史、扣费流水和旧表单草稿不清除。文字与截图提取、追问和确认都在同一聊天内完成。

`SubscriptionChatController` 在订阅 ViewModel 的作用域中组合现有主库、会话和附件接口；`SubscriptionChatCoordinator` 控制事务与业务绑定，`SubscriptionInterpreter` 只返回追问、拒绝或字段提议。界面继续调用 `BotComposerWorkspace` 和日程系统选择器、最近图片面板，日程本身的数据和模型流程不改动。

- 会话的草稿 `fieldsJson.chat` 保存当前解析消息、失败状态及待确认操作 ID，其他编辑、扣费草稿和聊天输入保持独立。发送消息、附件快照、清空本次输入和登记解析意图在同一事务完成。输入令牌写入 Room，已发送令牌阻止旧 Android saved state 把发送过的输入复活为新消息。
- 消息及图片关系是原始记录。原图经 `SubscriptionAttachmentRepository` 可靠复制到持久媒体目录，拍照使用现有 `media/originals/capture-staging`，成功导入后清理暂存副本。相册、文件和相机结果固定发起时的会话；当前解析接受图片，非图片导入失败不会被说成已识别。
- 每条最多5000字和4张图片。模型上下文为当前会话首条及最近消息，历史正文不超过24000字、图片最多4张，另附当前订阅字段快照和每条消息的本地发送时间。相对日期按原用户发言时间解释，当前时间只用于定位下一期。不读取其他订阅、未发送输入或未发送图片。
- 图片仅在用户发送或明确重试时生成最大长边2560像素、单张最多4 MiB的 JPEG 副本，处理旋转与透明背景，原文件不改动。通过配置模型的多模态 `image_url` 数据内容传递，不创建云端图片文件或业务后端；接口依据[百炼图片理解文档](https://www.alibabacloud.com/help/en/model-studio/vision)。凭据仍由既有加密配置读取，不进入提示词、UI状态或日志。
- 模型提议严格校验字段、数值类型、日期、币种及周期，不允许返回业务 ID、任意媒体路径、状态操作或批量订阅。金额不明、保险保费与保额不清、缴费周期与保障期限不清等情况在会话内追问。只提议当前订阅；另一个服务不能悄悄改名替换原卡片，已结束记录需明确恢复意图。
- 提议以既有 `subscription_operations` 的 `PENDING` 状态保存，用户点击确认或回复“确认”后，通过现有生命周期与 Repository 执行。确认再次检查会话绑定、原版本和当前日期，正式记录、变更历史、成功回复及待确认状态清理在一个 Room 事务内提交。失败继续保留待确认内容，重复确认复用同一操作 ID；输入有尚未发送的调整时不能确认旧提议。
- 网络期间不持有数据库事务。返回结果只在最新消息、目标记录版本与时区仍匹配时采用。用户继续发送会取消旧待确认操作，过期结果不能重新唤起旧提议。断网、鉴权、解析或本地写入失败保留原消息和截图；进程中断后明确提示重新解析，不在启动时自动重发网络请求。
- 聊天关闭不删除历史，新建会话创建新的独立草稿。“会话记录”按页恢复未完成及已绑定的聊天；消息按页加载。已有卡片从详情进入时恢复唯一会话，聊天或统计故障不影响已保存记录的离线浏览、编辑及账务登记。

专项测试使用合成图片与伪造模型传输，不调用用户配置的真实模型或发送个人截图。覆盖图片持久化和编码、文字／图片请求结构、严格输出校验、单会话隔离、解析与确认幂等、事务回滚、同会话修改、原历史保护、输入令牌恢复、解析中断、网络失败重试及并发记录变化。真实模型在手机上的识别质量、交互和网络恢复由用户验收。

## 第 6 阶段提醒实现（schema 17）

集成会话已为提醒独占预留 `16→17`，协调记录为共享 Git 元数据 `mebot-integration/migrations/subscription-reminders.json`。已按准确提交取得档案已验证的 schema 16 兼容基线，再只追加三张订阅专用表，保留既有58张表、全部数据与媒体，不改历史 schema 或旧迁移。档案实施复核已批准 `5242ae7`；最小代码基线为 `f36d6d3`、`2e3de37`，加任务令牌修复 `7e71cfb`。本分支在干净检查点按准确提交同步，协调不触发 main 合并或安装。

| 表 | 字段与约束 |
| --- | --- |
| `subscription_reminder_settings` | `subscriptionId` 主键并外键引用订阅；`enabled`、`minuteOfDay`（0..1439，默认09:00）、`revision`、`updatedAt`。提前量固定3天。 |
| `subscription_reminder_plans` | `subscriptionId` 主键并外键引用订阅；`cycleId`、`targetType`（预计扣费／有效期结束）、`targetDate`、`triggerAt`、`zoneId`、`subscriptionRevision`、`settingsRevision`、`generation`、`state`、`failure`、`updatedAt`；索引 `(state, triggerAt)`。每个订阅只保留一份当前计划。 |
| `subscription_reminder_deliveries` | 复合主键 `(subscriptionId, cycleId)` 并外键引用订阅；`state`、`attemptId`、`planGeneration`、`targetType`、`targetDate`、`startedAt`、`deliveredAt`（可空）、`updatedAt`；索引 `state`。每期交付独立保存，不随关闭提醒、改期或当前计划更新而删除。 |

自动续费按未确认的预计扣费周期，非自动续费或已登记关闭续费按有效期结束；同一周期切换目标或改日期、时刻仍只提醒一次。日付等短周期只处理当前适用的一期，不密集补发多期。到期归档与永久无日期项目不产生未来提醒。默认在目标日前三天09:00，在提前三天的窗口内可补交尚未交付的一次，目标日期已到则不追发旧周期。

非自动续费在有效期内更正日期不重置本期提醒；用户明确“登记已续期”或聊天中说明已续期、确认更长的新有效期后，以 `RENEW_TERM` 操作开始新一期。它不代表已确认扣费，不改写旧流水。到期归档后恢复并登记新有效期也会进入新周期；同一期的停用、改期与目标切换保留原交付额度。

计划在发送前重新核对当前业务版本、设置、周期与日期，取消失效任务。通知使用订阅专用渠道和稳定通知标识；Android 提交成功后才记录已提交，不声称用户已阅读。提交中断但能查到同标识通知时补记交付；无法判定结果时保留“不确定”状态，不自动重发同一期。明确的权限阻塞或提交失败保留可恢复状态，不提前消耗交付额度。

后台使用独立维护任务与一条最近的系统闹钟，开机、包更新、时钟／时区变化、恢复前台和业务变化时重建。采用普通本地通知，不沿用日程的持续响铃服务，不新增精确闹钟权限要求；系统调度可能延后，界面如实显示计划、权限与提交状态。依据 [Android 闹钟与后台任务文档](https://developer.android.com/develop/background-work/services/alarms) 和 [通知更新语义](https://developer.android.com/reference/android/app/Notification.Builder#setOnlyAlertOnce(boolean))。

公共接线仅涉及主库实体、DAO、保留数据迁移与版本；AppContainer 的订阅维护服务；清单内独立恢复／触发接收器；MainActivity 和 MebotApp 的订阅通知详情跳转。不改变日程业务、响铃服务、媒体格式或模型配置。通知开关、时刻、权限状态和跳转验收在订阅详情内完成。

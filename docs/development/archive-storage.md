## 已协调的主库变更

集成会话根据用户在本会话的明确授权分配 `15 → 16`（`MIGRATION_15_16`），只追加下列 13 张档案表，保留已有 45 张表及全部历史迁移。协调记录位于 Git 公共元数据目录 `mebot-integration/migrations/archive-storage.json`。正式数据接口和测试均使用同一个 `MebotDatabase`，不另建档案业务库。

| 表 | 职责 |
| --- | --- |
| `archive_records` | 稳定 ID、已确认内容密文、业务版本、时间及删除标记；保留最小墓碑以阻止旧请求复活记录 |
| `archive_sessions` | 会话及一次性目标绑定；新建时目标可空，保存后永久绑定一个档案 |

| `archive_messages` | 按会话隔离的消息密文与稳定顺序；消息重试不消耗后续输入 |
| `archive_operations` | 确认操作 ID、意图密文、原会话与目标版本、执行回执；同 ID 不得换内容使用 |
| `archive_assets` | 档案受保护附件元数据密文与可靠文件路径；不向公共明文媒体表写入档案原件 |
| `archive_session_assets` | 会话持有的附件、顺序与待发送状态 |
| `archive_message_assets` | 发出消息时的附件快照；复合外键防止关联其他会话的附件 |
| `archive_record_assets` | 正式档案的附件顺序；同一事务与正式内容提交 |
| `archive_embeddings` | 按档案、业务版本、模型配置与分段序号保存的向量及检索文字密文，可重建 |

## 数据保护与文件方案

- AES-256-GCM，随机 IV，使用包含用途和记录 ID 的附加认证数据，防止密文跨记录替换。Android Keystore 独立管理档案密钥；已有密文而密钥不可用时拒绝写入，不静默生成新密钥覆盖。
- 附件原件写入 `filesDir/archive/originals` 的认证加密文件，Room 保存密文元数据及关联。档案文件格式与公共媒体原件不同，因此不对 `LocalMediaStore` 或公共 `media_assets` 增加明文降级/跨 Bot 去重行为。
- 临时导入先加密写入暂存文件并完成同步，再发布文件并事务登记；失败保留可恢复清理信息。按需解密的预览副本仅位于档案缓存，认证通过才交给调用方，使用结束删除；清缓存不删正式原件。
- 本批无需改写 `MediaDao.deleteIfUnused`：公共媒体清理只处理 `media/originals`，档案清理只处理 `archive/originals`，二者不得互相删除。

## 必须保证的事务边界

1. 首次确认同时完成正式档案、会话唯一绑定、附件关联、操作回执和索引任务。重复确认返回相同结果，新操作不能在同一会话再创建第二份档案。
2. 更新只能作用于会话已绑定对象，检查档案/草稿版本；任一步失败全部回滚。模型上下文只从当前会话和它绑定的正式档案读取。
3. 消息、附件快照与清空本次输入在同一事务中提交；同消息重试不能清掉后来输入或其他会话附件。
4. AI 请求绑定会话、草稿版本和请求令牌；过期、取消、被替代或目标已删除时拒绝写回。
5. 索引写回绑定档案版本、当前模型配置和执行令牌；每次领取任务由 Repository 内部生成新的 UUID，恢复后不能沿用后台任务的稳定 ID；更新/删除/重建会立即使旧向量和旧任务失效。

正式删除保留最小绑定墓碑，并撤销候选、当前索引和执行令牌；聊天历史、操作回执及其附件继续保留用于本会话回看。它不是聊天历史的安全擦除接口，后续管理页面须明确区分删除档案与清理历史的范围。

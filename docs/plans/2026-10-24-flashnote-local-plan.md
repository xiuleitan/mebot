日期：2026 年 10 月 24 日。更新：2026 年 10 月 25 日。状态：步骤一至六已实现；0.18.0 已通过步骤七的自动化检查与构建，步骤八已安装到连接的手机，交付用户验收。

附件增量已接入：相机、相册、文件选择、本地复制、草稿恢复、卡片首图与详情预览均可用；主库 schema 10 保留现有数据。附件交付产物 0.19.1 已通过全量 295 项测试及独立 Lint／构建，并成功安装到手机，见 [闪念页面说明](../design/flashnote-ui.md)。

闪念 Bot 用于记录没有执行日期或截止日期约束、但希望尽量完成的未来事项。每件事项自动记录创建日期和时间，用户以后打开卡片查看、修改并完成；事项在手动完成或删除前持续保留。

闪念作为 mebot 中与「日程」并列的独立入口。日程围绕具体执行日期和时间组织事项，闪念围绕未完成事项组织内容。用户无需指定执行日期或截止日期；首次成功保存时自动记录创建时间，供日期展示和列表排序使用。事项无逾期判断或自动归档，编辑、完成和恢复均保留原创建时间。

## 功能范围

| 功能 | 操作与结果 |
| --- | --- |
| 快速记录 | 输入想做的事情，点击保存，直接新增一张未完成卡片并自动记录创建时间。正文即可保存，不要求标题、执行日期或模型理解 |
| 卡片查看 | 单列卡片展示标题、内容摘要、图片和创建时间，点击打开详情，阅读完整内容 |
| 编辑和删除 | 详情中修改正文或直接删除；编辑保留当前完成状态，删除后卡片从对应列表移除 |
| 状态区分 | 点击「未完成」或「已完成」按钮，只显示对应状态的卡片；两者互斥选中 |
| 完成操作 | 点击卡片打开详情后标记完成；已完成事项在详情恢复为未完成，列表不提供独立状态按钮 |

新建事项默认未完成。完成后保留正文并进入已完成列表；查看、编辑和时间经过都不会自动改变状态。恢复为未完成后重新进入未完成列表，原创建时间不变。

按用户补充，本次移除每日回顾、通知权限、后台提醒调度及相关数据表。旧记录由用户后续手动录入，不开发旧 JSON 导入、旧编号映射或数据搬迁；原方案中的导入导出阶段一并移除。

本次实现范围限于上述记录和处理流程。草稿保存、操作去重和数据库升级属于可靠保存所需的内部能力，不增加独立管理页面。

## 页面与操作流程

侧栏在日程下增加「闪念」入口，进入后展示独立页面，沿用 mebot 的主题、字体和导航方式。

| 区域 | 规划 |
| --- | --- |
| 顶部 | 页面标题，以及「未完成」「已完成」两个切换按钮；首次进入默认选中未完成 |
| 内容区 | 默认采用单列横向卡片；左侧显示标题和内容摘要，右侧显示圆角图片，下方显示创建日期时间，全文在详情中查看 |
| 卡片操作 | 点击卡片任意区域只查看详情；完成／恢复统一在详情底部操作 |
| 底部 | 快速输入区和保存按钮，支持多行文字 |
| 详情 | 完整正文、创建时间、编辑、删除、完成或恢复操作；编辑可以保存或取消 |
| 空状态 | 未完成为空时提示可以记录想做的事情，已完成为空时提示尚无已完成事项 |

卡片标题不套用日程卡片的短标题限制，内容摘要可以省略，正式记录的全文不截断；换行、链接、数字和类似旧命令的文字都按原文记录。当前 UI 独立提供标题、正文和图片的展示字段，正式录入和图片持久化均已接入。

「未完成」和「已完成」两个列表均默认按创建时间从早到晚排列，最早创建的事项在最前；创建时间相同时使用稳定 ID 排序。编辑时间、完成时间及恢复操作都不改变事项相对于其他卡片的创建顺序。

保存成功后清空本次输入，并切到未完成列表。新创建的卡片按创建时间加入末尾，随后滚动定位到该卡片，不临时插到列表顶部；保存失败保留输入并提供重试。

编辑打开独立草稿，取消时不改变正式记录，保存成功后才更新卡片。删除沿用直接执行的方式，不增加回收站。两个状态列表保留各自的浏览位置，切换按钮、卡片移入移出和详情开合使用自然衔接的动画。

系统返回先关闭编辑或详情、侧栏，再返回上一页。动画遵循系统设置，连续操作与手势取消时平滑恢复；大字体、暗色主题和触控范围沿用现有 Android 可用性要求。

## 本地数据设计

所有结构化数据进入现有 `mebot.db`，通过 Room 和 Repository 访问，闪念不另建数据库。

| 表 | 主要字段 | 用途 |
| --- | --- | --- |
| `flashnotes` | `id`、`title`、`content`、`status`、`createdAt`、`updatedAt`、`completedAt`、`revision` | 正式事项，状态仅为未完成或已完成 |
| `flashnote_drafts` | `key`、`title`、`content`、`editingNoteId`、`baseRevision`、`revision`、`updatedAt` | 快速输入和编辑草稿；新建 key 使用预分配 UUID，编辑草稿通过外键关联事项 |

按状态与创建时间建立查询索引，两个列表统一使用 `createdAt ASC, id ASC` 排序。`createdAt` 在正式事项首次保存时生成，此后不改写；`updatedAt` 和 `completedAt` 记录各自操作时间，不参与默认排序。创建时间戳在本地持久化，展示时按手机时区转换为日期和时间。内部采用 UUID 标识事项，用户无需记忆或输入编号。正文、状态及草稿均保存在本机，断网或未配置模型时全部功能可用。

保存规则如下：

1. 非空正文或至少一份附件即可保存，读写避开界面线程。只有事务提交成功，界面才报告保存成功并显示正式卡片。
2. 新建草稿使用预分配 UUID 作为正式记录 ID，同一次提交与重试复用该 ID，防止重复创建。
3. 保存事务校验草稿仍存在且 revision 匹配，正式记录写入和相应草稿清理一起提交。草稿已清理时核对正式记录，存在则视为已经提交；不存在则拒绝迟到请求，避免删除后被重试重新创建。
4. 编辑校验记录 revision，失败时保留原记录和编辑内容，不无声覆盖较新的修改。迟到的草稿自动保存也需校验 ID 与 revision。
5. 首次完成写入完成时间，重复完成不改写该时间；恢复未完成时清空完成时间。完成、恢复和删除均以数据库结果更新列表。
6. 删除同时清理关联编辑草稿，旧回调不能重新写回。已持久化的新建草稿在重开后恢复，但不会自动提交为正式事项。
7. 从开发时最新数据库版本增加保留数据的迁移，保留日程、周期、会话、附件、封面及模型凭据，不清库重建。

## 实施顺序

开发依次完成以下八步。第一至三步建立可持久化的数据与状态，第四至六步形成完整操作流程，第七、八步完成验证及安装交付。

### 步骤一 扩展主数据库

已完成：新增 `FlashnoteEntities.kt` 和 `FlashnoteDao.kt`，定义事项表、草稿表、状态查询和创建时间索引，并注册到现有 `MebotDatabase`。主库升级到版本 9，新增 `8 → 9` 的保留数据迁移，导出 schema 9 并保留原迁移链。

完成标准：新库可以读写闪念；现有库升级后，日程、会话、附件、模型配置及日程提醒相关数据完整保留。

### 步骤二 实现本地业务操作

已完成：新增 `FlashnoteRepository`，实现新建、查询、编辑、完成、恢复、删除及草稿保存，并通过 `AppContainer.flashnotes` 提供入口。统一处理非空校验、事务提交、重复请求和 revision 冲突；创建时间在首次正式保存时生成，此后保持不变。两个状态列表均按 `createdAt ASC, id ASC` 查询；新增 18 项业务专项测试。

完成标准：仅依赖本地数据库即可完成所有业务动作；保存失败不丢输入，重复提交不增加事项，编辑或改变状态不改变原创建时间，已删除记录不会被旧请求写回。

### 步骤三 接入页面状态

已完成：新增 `FlashnoteViewModel`，使用 `AppContainer` 的 Repository 管理状态筛选、输入草稿、选中 ID、数量、详情和保存结果。默认 SavedState 工厂在 Activity 中创建并注入页面。正式卡片与详情订阅数据库，两个列表分别保留浏览位置，页面隐藏时停止查询，草稿与正式写入串行执行。新增 11 项页面状态测试。

完成标准：数据库变化能同步到列表与详情；切换状态不混入另一类事项；保存期间限制重复操作，失败保留内容并允许重试。

### 步骤四 完成入口和主页面

已完成：侧栏、`BotDestination`、`MebotApp` 和 Activity 接入真实闪念页面；两个状态按钮、数量、标题／摘要卡片、创建日期、多行输入、保存和空状态均来自实际本地数据。保存成功才清空输入并定位到新记录；失败保留内容和同一提交标识，支持重试。示例仅保留在 Android Studio 预览。

完成标准：从侧栏可进入闪念，首次默认显示未完成；输入后可创建卡片，列表最旧在前，新事项排在末尾并可定位查看；返回路径和原日程入口正常。

### 步骤五 完成卡片详情及状态操作

已完成：详情显示可滚动和选择复制的完整正文，底部提供完成／恢复、编辑及删除三个操作。编辑独立保存标题与正文草稿，支持保存或取消；关闭保留编辑草稿，取消删除对应草稿并保留正式记录。卡片主体点击只打开详情，完成／恢复集中在详情底部；状态写入后更新数据库订阅列表，删除成功平滑关闭详情。

完成标准：能走通「记录 → 查看 → 编辑 → 完成 → 恢复 → 删除」；长正文不截断，编辑取消不修改正式记录，两个列表始终按创建时间排序。

### 步骤六 补齐恢复与流畅体验

已实现：新建与编辑草稿均在离开或切后台时刷新，重开可恢复已落库内容，互不覆盖。写入队列独立于页面生命周期，已开始的保存跨关闭完成；排队编辑关闭后不再打开，取消／删除后的迟到输入不会恢复记录。列表切换与卡片移入移出沿用动画；详情采用日程相同的悬浮圆角、跟随位置的阴影及遮罩同步入场，编辑／查看自然切换。正文独立滚动，操作区固定，使用窗口约束和主题色。所有数据库读写避开界面线程；实际手机上的键盘、大字体、动画及返回手势交由用户按验收清单检查。

完成标准：断网或未配置模型仍可完整使用；重开后正式记录与已保存草稿保留，草稿不会自动变成事项；连续点击、切页及取消手势不会造成跳动或残留遮罩。

### 步骤七 完成自动化检查和构建

已完成：本轮新增 17 项页面状态测试，包含全文编辑、独立草稿、取消、失败回滚与重试、完成恢复、旧版本删除、删除后迟到请求及关闭期间的保存。全量 268 项测试通过（24 个测试类，0 失败／错误／跳过），覆盖既有日程、附件及提醒测试；Lint 无错误，Debug 构建成功。

完成标准：相关自动化测试及 lint 通过，Debug APK 构建成功；同步 README 中实际已交付的功能和验收说明。

### 步骤八 安装到手机并交付验收

已完成：0.18.0（versionCode 61）通过 `installDebug` 安装到已连接的 PMW110（Android 17），Gradle 返回 `Installed on 1 device`。未代替用户操作手机进行功能测试；按下方清单交付验收。安装命令：

## 开发验证与手机验收

开发验证重点为主库升级保留既有数据、重复提交、事务失败回滚、编辑冲突及删除后迟到请求失效。以下为完整功能接入后的验收清单；步骤一的升级及数据保留验收见 [本地数据基础](../design/flashnote-storage.md#手机验收)。

| 操作步骤 | 预期结果与相关回归 |
| --- | --- |
| 断网且不配置模型，进入闪念，输入一件想做的事并保存 | 无需填写执行日期，自动记录创建时间，新增一张显示创建日期的未完成卡片，保存成功后输入清空 |
| 输入多行长正文保存，点击卡片查看 | 卡片显示预览，详情显示完整正文及换行，不套用日程短标题限制 |
| 点击「已完成」和「未完成」两个按钮来回切换 | 仅显示所选状态的卡片，选中态清楚，各自浏览位置保留 |
| 依次创建事项 A 和 B，编辑 A，再先完成 B、后完成 A，最后恢复两项并重开 | 两个列表都按创建时间将 A 排在 B 前面；编辑、完成和恢复不改写创建时间。新建事项继续排在较旧事项后面 |
| 完成一件事项，切到已完成，再恢复未完成 | 同一事项进入正确列表，重开后状态保留，不新增重复记录 |
| 打开卡片编辑并保存，再次打开；另一次编辑选择取消 | 保存后的正文保留，取消不修改正式记录，编辑不改变完成状态 |
| 删除卡片，切换列表并重开应用 | 已删卡片不再出现，旧草稿或迟到请求不能重新创建 |
| 连续点击保存，失败后重试，退出再重开含输入的页面 | 同一次保存只有一条记录，失败保留内容，已落库草稿可恢复且不会自动提交 |
| 过几天再打开未完成列表 | 事项继续保留原创建日期及最旧在前的顺序，不因未设置执行日期或时间经过而过期、归档或自动完成 |
| 覆盖升级后往返日程和闪念，切换主题、放大字体并连续开关侧栏和详情 | 既有日程及附件等数据保留，状态按钮和正文可读，动画与返回路径无相关回归 |

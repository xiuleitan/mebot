# 首页单 Bot 路由与原生任务交接

用户确认：首页正文是唯一决策输入；正文开头的彩色`@Bot`是可点击、可整块删除的文本路由标记，纯附件不能首次发送；每次仅一个 Bot，错误由用户手动改选。发送后复用原 Bot 处理方式，闪念直接保存，不增加聊天浮窗。

## 接口与边界

- 使用阿里百炼 `decision-model-preview` 的 System One `choice` 问题。只传当前文本和固定职责，不传图片、文件、附件名、其他任务或历史；不使用 Chat Completions 假装决策协议。
- 只提供五个有效选项，不提供other或未归类选项；按五个Bot中最高概率选择，不设置置信度门槛。服务未返回概率时接受其选中的有效Bot；网络、鉴权和响应格式错误仍独立提示，不能伪装成成功分类。
- `schedule`／日程、`flashnote`／闪念、`dayima`／大姨妈、`subscriptions`／订阅管理、`archive`／档案共用稳定注册表。业务语义优先于日期字样；例如经期日期和会员有效期分别属于原业务。
- 从最后一次文字变化开始计时，连续1.5秒未变化后请求一次；持续修改时重新计时，不调用模型；判断后文字未变化不重复请求。修改文字取消旧请求，结果按请求代次校验。手动选择取消当前自动判断；之后正文发生变化，停满1.5秒仍重新判断。仅更换或删除标记不触发新判断，删除后保持无标记，发送禁用。无文本不请求；错误／超时／配置不足时保留草稿，允许手动选 Bot。
- 发送时固定唯一 Bot；后续聊天文本交给原 Bot，不重新分类或跨任务混入历史。

## 分类边界与示例验收

决策请求提供总规则（`instructions`）和五个Bot简洁、正向的职责选项（`criteria`）。本轮采用真实接口对比后的英文判定说明，并保留必要的中文时间表达及经期术语；少量对照例子放在总规则中，避免每个选项都混入其他类别及大量反例。先判断明确的经期、订阅、建档业务；其余普通行动，有执行时间归日程，无执行时间的普通待办和想法归闪念。明天、今晚、待会儿、下周、每天均可作为执行时间，不要求具体时刻。“记得”“看一下”“整理一下”不能覆盖这个区分。判断依然由决策模型完成，本地不按关键词强制改写其结果。

## 数据与恢复

- 新增schema25，只追加路由配置与发送回执，冻结1→24已安装结构和迁移。
- 先建立持久发送回执，使用草稿revision、文本和有序附件ID生成快照标识；原Bot首条消息与首页清空在同一事务提交。重复提交回到同一回执。数据库失败回滚并保留首页原输入。
- 每次交接建立独立Bot任务，原Bot已有草稿保留。日程创建页清理时跳过首页已交接会话。
- 普通媒体复用已有可靠本地资产；档案按其原加密格式复制到档案附件，并使用稳定ID重试。交接成功后释放不再被其他记录引用的首页原副本。
- 路由配置保存Room；密钥继续使用现有Android Keystore保护的模型设置。预览空间地址通过忽略的本机配置注入，源码中不硬编码用户地址。

## 界面复用

首页使用共用输入栏的文字区域插槽显示路由标记，其他Bot仍使用原输入组件。标记直接存在首页Room草稿文本中，不另存一份有效目标；发送状态从当前开头标记解析，防止删除后沿用旧目标。自动插入或更换标记保留正文光标、选区和输入法组合范围。首页发送快照保留完整草稿用于事务校验，实际交给各Bot的消息只包含正文。复用schema25，无数据库结构变化。

首页承载原 `ScheduleComposerWorkspace`、`DayimaComposerWorkspace`、`SubscriptionComposerWorkspace`、`ArchiveComposer`。聊天文本、附件、追问、确认、手动编辑、保存及失败重试由原业务负责。收起后返回首页输入，仍保留原任务会话。

闪念调用原仓库保存并排队生成标题，给出保存反馈，无聊天浮窗。其他Bot不接受的附件明确报错，不静默丢掉。

## 手机验收

1. 输入“明天买菜”，停止输入后出现蓝色`@日程`；发送后在首页看到日程原聊天和结果卡片，继续说“改为后天”只修改该任务。
2. 输入无日期的普通想法，显示`@闪念`；发送后直接保存并留在首页。重复点击不重复生成。
3. 点正文开头的彩色`@名称`改选另一个Bot，正文保持不变；再次编辑正文并停满1.5秒，应重新判断。光标在标记后按一次退格应整块删除，正文保留；无标记、名称错误、只有标记无正文或纯图片／文件均不能按钮发送或键盘发送。
4. 分别提交经期记录、订阅说明和档案资料，核对原有追问、候选确认与保存、附件预览／编辑仍可用。订阅或经期携带普通文件时明确提示并保留输入。
5. 断网或配置错误时可手动选Bot，输入和附件不丢失；目标Bot后续网络失败沿用原重试流程。检查各Bot原有草稿仍保留，以及任务会话关闭、页面重开和字体缩放。

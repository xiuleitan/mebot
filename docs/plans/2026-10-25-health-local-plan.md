## 功能与页面

侧栏增加「大姨妈」入口，与日程、闪念并列，页面标题同步使用「大姨妈」。页面沿用 mebot 的主题、字体、返回路径及过渡动画。

| 区域 | 内容与操作 |
| --- | --- |
| 顶部出生日期入口 | 标题旁显示年龄小按钮，未设置时显示「生日」；点击打开原日期输入窗，查看、更改或移除完整日期 |
| 周期日历 | 日历上方左侧为预计日期、右侧为当前估计阶段；两个月共用连续周表，左侧显示月份；下方按经期、卵泡期、排卵期、黄体期顺序排列一行四个特点按钮 |
| 记录与历史 | 记录今天、补记历史日期、直接更正日期、删除；显示原始开始日期及相邻两次间隔，全部历史可按需浏览 |
| 历史统计 | 仅两张图：周期天数分布图、时间与年龄趋势图；时间和年龄共用第二张图的查看模式，支持回查原始记录 |
| AI 对话 | 底部自然语言输入，展开本次聊天；支持操作、追问、数据查询及健康相关咨询，提供新对话与对话记录入口 |
| 提醒设置 | 两类提醒的开关、提醒时刻和准备提醒的提前天数 |

核心记录仍为每次经期第一天，首版不要求逐日填写、结束日期或经量。与本次经期有关的补充情况可以作为文字备注保存，不强制用户填写症状量表。

出生日期通过主界面顶部按钮填写或修改，保存后立即更新年龄展示，取消输入不修改原值。日期校验拒绝未来出生日期。未填写时，记录、分布统计、按年份查看趋势和提醒均可使用，第二张图的年龄模式提示填写出生日期。出生日期只用于年龄计算，不据此补造任何历史记录。

## AI 对话

### 每次聊天独立保存

一次新聊天建立一个独立会话，可包含多轮补充与追问，例如先说「今天来了」，再说「刚才记错了，是昨天」。会话中的消息、输入草稿、待补充问题和执行结果按会话 ID 保存到本机，供恢复本次未完成聊天或查看历史。

发起新对话时使用新会话，不自动带入其他聊天的正文、摘要或待补充问题，也不维护跨会话的长期记忆。历史聊天仅作为聊天记录保存；已保存的经期日期、备注、出生日期和提醒规则仍是独立业务数据，可以在任何新会话中按需读取。

每次请求只携带本次聊天所需的上下文，再按意图读取最新本地数据。例如新聊天询问「上次是什么时候」，直接查最近一次经期记录；问「今年 28 天有几次」，读取本地统计结果。新会话不依赖模型记住以前聊过什么。

删除或清空一个聊天只影响该会话及其草稿，已经保存的经期记录与提醒保留。重开应用可恢复尚未完成的本次会话；用户主动新建的聊天始终与旧会话隔离。

### 可直接表达的请求

| 用户说法 | 预期处理 |
| --- | --- |
| 今天来大姨妈了 | 保存今天为开始日期，展示实际保存的记录及更新后的预测 |
| 上周五开始的，忘记记了 | 根据手机本地日期解析明确日期，补记并重新计算相关周期 |
| 刚才日期记错了，是昨天 | 在目标明确时更正原记录，保留其余信息；目标不明确时先追问 |
| 把 10 月 3 日那条删掉 | 删除明确对应的记录，重新计算相邻间隔、图表和提醒 |
| 今天开始，腰有点酸，也帮我记一下 | 保存开始日期及相关文字备注，不把症状推断为诊断 |
| 我今年有多少次刚好是 28 天 | 本地统计对应年度的完整周期数量，再由模型组织回答 |
| 近两年是不是比以前间隔更长了 | 调用本地分段统计，回答范围、样本数和周期变化，附可查看的图表范围 |
| 提前两天提醒我，改成晚上八点 | 保存本地提醒规则；之后执行提醒无需再次调用模型 |
| 这次不舒服，想了解可能和什么有关 | 进行健康相关对话，结合用户主动提供的情况解释；需要信息时追问 |

相对日期按手机当前日期和时区解释；经期发生日期按日历日期保存。实际记录不能写到未来。诸如「可能要来了」只表示咨询或预计情况，不能自动写为实际开始；纯咨询不会自动变成经期记录。明确要求保存的补充情况关联到对应记录，尚无经期开始记录时可作为带日期的独立文字备注保存。

明确的单条操作直接执行，成功后展示对应记录；仅当日期、目标或意图不清楚时追问。一次请求包含多个明确操作时，先完成全部参数校验，再在事务中提交整组业务操作；有歧义时整组暂存并追问，不出现部分保存却报告全部成功。删除目标不能由模型猜测。

### 模型与本地执行

复用现有模型设置、HTTPS 传输、凭据加密及错误分类。大姨妈 Bot 使用独立的意图、查询和回复协议；现有日程解析器会拒绝查询与无关请求，不能直接作为本 Bot 的解析器使用。

模型负责理解和文字回复，本地代码负责日期校验、目标定位、事务保存、统计计算、预测和通知调度。模型不能直接写库，不能以生成的一段文字作为执行成功的证据。涉及记录和数值的回复应绑定本地执行结果；输入含糊、模型输出无效或保存失败时保留输入并显示真实状态。

查询通过有限的本地数据接口完成，例如指定时段记录、天数分布、分段统计；模型不生成 SQL。汇总结果需附带统计范围、有效周期数、排除数量和业务数据版本，回复中的关键数字由这些结果提供。统计过程中数据发生变化时重新读取，避免用旧结果解释新图表。

只发送本次聊天及当前请求所需的数据。普通记日期不上传全部历史；全历史问题优先在本地聚合后发送统计摘要。出生日期默认留在本地，必要时提供相应年龄或年龄分组即可。其他大姨妈会话、日程与闪念的聊天记录不自动进入本次上下文。

AI 咨询中的推测与本地已记录事实分开表述。涉及身体状况时提供相关说明和必要的就医提示，不根据一组周期数值直接给出病因、绝经或用药结论。

断网、未配置 Key 或模型失败时，对话显示可辨认的错误并保留待发送内容；手动记录、更正、删除、历史、图表、本地预测与已保存提醒继续可用。

## 周期统计规则

### 一个周期怎样计算

周期长度为两次相邻经期第一天之间的日期差。例如 10 月 1 日与 10 月 29 日开始，两者相隔 28 天。N 条有效且连续的开始记录最多形成 N−1 个已完成周期；最后一次开始到今天仍未结束，不加入历史分布，也不作为已完成的超长周期。

原始日期排序并按同一天去重。每个周期均能定位到起止两条记录；补记、更正或删除后重新派生相邻周期。默认覆盖全部已记录历史，取消旧版查询只展示近两年的限制，提供近一年及自选时间段作为浏览方式。

跨年、跨生日和日期筛选统一以周期开始日归组，筛选后再查找其下一次开始日期，不先截断原始日期列表再计算间隔。图表明示这一口径，并可查看完整起止日期，避免把跨年周期漏算或重复计算。

漏记可能造成很长的间隔，真实较长周期也可能存在。保留原始数据，不仅凭天数自动认定漏记。用户可将一个跨度标记为「有漏记／记录不连续」或标记不适用于普通周期比较的阶段，并填写说明；这些跨度仍在历史中展示，单独列出数量，默认不参与常规分布、个人基准、趋势汇总和预测。未标记的间隔保留在统计中，图表提供回查与更正入口。

### 周期天数分布图

主图采用直方图，横轴为周期长度（天），纵轴为出现次数。默认按 1 天统计，能够直接看到 26、27、28、29、30 天分别有多少次。点击某个柱子可查看对应周期及起止日期，计数同时提供占有效周期总数的比例。极长跨度导致横轴难以阅读时可聚合尾部，但须显示范围与次数，允许展开查看，不能截掉尾部数据。

| 比较方式 | 展示规则 |
| --- | --- |
| 28 天基准，默认选中 | 少于 28 天、恰好 28 天、多于 28 天分别统计，精确回答用户关心的问题 |
| 个人典型周期 | 使用当前统计范围内有效周期长度的中位数，显示基准值与样本数，观察相对个人历史的偏差 |

图表用「比基准短」「与基准相同」「比基准长」表示统计分类。28 天是比较参照，不能据此将 27 天、29 天直接标为异常。美国卫生与公众服务部女性健康办公室说明，周期存在个体及月际差异，28 天并非人人固定的长度。[周期说明](https://womenshealth.gov/menstrual-cycle/your-menstrual-cycle)

相对 28 天的差值和相对一次事先预测的提前／推迟分开。以后若展示「比预测晚了几天」，必须读取当时保存的预测快照，不能使用纳入这次实际日期后重算的结果作比较。

### 时间与年龄趋势图

分布图回答频次，第二张「时间与年龄趋势图」保留每个周期发生的顺序，并在同一区域切换时间或年龄查看方式。时间模式的横轴按实际开始日期连续排列，纵轴为周期长度；每个点代表一个完整周期，点击可查看日期、长度及当时年龄。默认叠加最近 6 个有效周期的滚动中位数，满 6 个后才开始显示，帮助看清持续变化；记录不连续或被排除的阶段断开趋势线，不连接其两侧来制造连续变化。

填写出生日期后，以每次周期开始日计算实际周岁，支持按年份和年龄查看汇总，不使用当前年龄回填全部历史。出生日期更正只重算年龄标签，不改原始日期与周期长度。

按年份或周岁汇总时展示中位数、居中一半周期的范围（第 25 到第 75 百分位，采用同一插值规则）和周期数。同时观察周期长度与波动：可能整体变长、整体变短，也可能中间值稳定但波动增大。某组少于 3 个有效周期时只展示原始点和数量，不绘制该组汇总带；此门槛用于防止稀疏图形误导，不表示达到门槛就能得出医学结论。

年龄趋势不预设「年纪越大一定越晚」。真实世界研究在其样本中观察到部分年龄段的平均周期缩短及后期波动变化，群体关联也不能用来确定某个人变化的原因。[研究原文](https://www.nature.com/articles/s41746-019-0152-7)

AI 可对比用户指定的两个时期，例如最近一年与前一年，列出各自周期数、中位数和分布变化。两组各少于 3 个有效周期时不自动总结整体趋势；不足一年历史时不生成年龄变化结论。界面不提供缺少依据的健康分数或显著性标签。

## 预测与提醒

第一版延续旧版的确定性预测规则：至少两条有效开始日期，使用最近最多 6 个连续有效周期，越近权重越高；最新开始日期加加权周期得到预计日期，再根据历史波动生成前后 2～7 天范围。该范围是算法给出的日期估计范围，不显示为统计置信区间。

被标记为漏记或特殊阶段的跨度不进入预测；跨越这些阶段不连接取样。新阶段有效间隔不足时显示记录不足，避免强行使用很久以前的周期给出当前估计。

保留两类提醒，分别提供开关：

1. 准备提醒：默认预测范围开始前 1 天，可修改提前天数。
2. 缺失记录提醒：预测范围结束后的次日起，没有新记录时提醒补记；文案说明缺少新记录，不断言经期实际推迟。

默认提醒时刻沿用 12:00，可通过页面或对话修改。使用 Android 本地通知，不依赖模型或常驻业务服务器。通知可进入大姨妈页面并补记。已有日程的系统调度与恢复经验可以复用；大姨妈提醒使用自己的业务状态及通知渠道，默认采用普通通知，不沿用日程连续响铃的交互。

新增、更正、删除记录和修改配置后，使旧版本提醒失效，再生成新计划。应用重开、开机及时间／时区变化后恢复有效计划；同一业务提醒只交付一次。错过的准备提醒不在预测窗口已结束后补发，缺失记录仍存在时最多补发一次；权限不足时显示实际状态，不影响记录保存。

## 数据与工程落点

全部结构化业务数据继续进入 `mebot.db`，采用 Room、Repository、ViewModel、Compose 的现有分工。下列为职责划分，具体 schema 在实施数据阶段确定。

| 数据职责 | 保存内容 |
| --- | --- |
| 出生日期 | 日期及修改版本，由主界面顶部输入 |
| 经期记录 | 开始日期、创建与修改时间、版本；同日记录唯一，相关备注通过关联读取 |
| 健康文字备注 | 发生日期、文字、可选关联记录；删除经期记录时保留独立备注并解除关联 |
| 统计跨度标记 | 两个起止记录 ID、排除原因及说明；边界变化后重新校验并提示复核，不静默套用到新跨度 |
| 独立聊天与操作 | 会话 ID、会话状态及创建时间；按会话关联消息、未发送输入、待补充问题、执行结果和去重标识 |
| 提醒配置与交付 | 开关、时刻、提前天数、业务版本、登记及交付状态 |
| 预测快照 | 计算时刻、使用的记录版本、预计日期和范围，关联通知计划 |

周期长度、频次分布、年龄、滚动统计均为可重建的派生结果，不能取代原始记录。全部历史按需读取；本地计算及网络请求避开界面线程。数据变更后图表与查询摘要一起失效更新，缓存不能使已删除记录重新进入统计。

记录写入、操作去重及相关业务状态更新使用事务；数据库提交后再报告成功。模型请求、页面重开或用户重试均不能重复新增。同一操作执行时校验数据版本，删除后的迟到回复不得重建旧记录。异步请求与待补充问题绑定会话 ID，新建聊天后旧回复不能写入新会话；已作废会话的迟到结果不得继续执行业务。

从实施时最新 schema 添加保留数据的迁移，不固定沿用当前版本号，不影响现有日程、闪念、附件、主题和模型配置。共用网络传输与凭据能力，大姨妈 Bot 的查询、记录和提醒逻辑按业务独立组织，避免直接扩展日程专用协议。

旧项目仅参考规则，移除 Matrix、房间和消息同步、R2／S3、Python 常驻服务及相关凭据。旧记录是否导入及导入格式单独确定；本方案不读取旧项目真实数据。真实出生日期与历史尚未提供，展示示意统一标记为模拟数据，不写入应用业务库。

## 开发步骤顺序

依次完成以下八步。步骤一至六已实现，步骤七至八待开发。先完成本地记录与计算，再接入真实页面、两张图和 AI，确保对话读取的数据与页面一致；每批在功能分支构建装机，整体合并按用户要求进行。

### 步骤一 建立本地数据基础

在现有 Room 主库中增加出生日期、经期记录、文字备注、跨度标记、独立聊天、提醒配置和必要操作状态，提供 DAO、索引和保留数据的迁移。会话从一开始就按独立 ID 组织，避免后续把全部消息拼成一个长期会话。通过现有 `AppContainer` 提供数据访问入口。

已完成：新增九张大姨妈业务表、`DayimaDao` 和 `AppContainer.dayimaStorage`，主库通过 11→12 保留数据迁移升级至 schema 12，导出并保留升级前后的 schema。10 项真实 SQLite 专项测试验证重开恢复、会话隔离、关联清理、版本冲突、事务回滚与旧数据保留。本轮尚未接入页面或业务 Repository。

完成标准：正式记录、草稿和每个聊天可以分别持久化；已有日程、闪念、附件及模型配置在升级后保留。

### 步骤二 实现记录与资料的本地操作

实现出生日期保存与修改，经期开始日期的新增、补记、更正、删除，相关备注及漏记跨度标记。统一处理未来日期、同日重复、编辑版本冲突、事务失败和重复提交；记录变更后产生一致的数据版本。

已实现：`DayimaRepository` 及 `AppContainer.dayima`，以稳定请求和事务回执处理重试，提供版本约束的记录、备注、出生日期与跨度操作。12→13 迁移新增回执及持久待复核状态；35 项大姨妈专项测试验证业务与升级。页面仍按步骤四接入，当前没有自动生成的示例记录。

完成标准：通过本地数据层即可完成全部记录操作；重试不新增重复记录，失败不误报成功，删除后的旧请求不能重新创建数据。

### 步骤三 实现周期统计与预测

从真实开始日期派生完整周期，实现全部历史及日期范围查询、逐日频次、28 天与个人基准比较、年龄计算、滚动中位数和分组统计。处理漏记跨度、跨年、跨生日及当前未完成周期，再接入旧版的确定性预测规则。向图表与后续 AI 提供同一套本地查询结果。

已实现：`DayimaStatisticsCalculator` 与 `DayimaRepository.statistics`、`compareStatistics`、`observeStatistics`；查询与订阅从同一事实快照计算，使用提交版本和本地日期刷新。新增 32 项专项用例，覆盖分布、年龄、断点、加权预测及数据库订阅。本步沿用同步的 main schema 14，功能分支自测与构建通过后安装手机，保持应用数据。

完成标准：统计、年龄和预测离线可用；新增、更正或删除日期后结果一起更新，样本不足和排除数量真实可见。

### 步骤四 接入大姨妈主界面

接入侧栏入口、页面路由和 ViewModel，展示名称统一为「大姨妈」。顶部提供「填写出生日期／修改」按钮及简单日期输入弹窗，下方展示经期概览、手动记录入口和历史列表；详情支持查看、编辑、删除及备注。页面使用真实本地数据和空状态。

已实现：侧栏与 `DayimaRoute`、`DayimaViewModel` 接线，顶部出生日期、经期与预测概览、今天／补记、开始历史与按需加载的独立备注、详情更正／删除／备注，以及周期标记和待复核入口。页面只在可见时订阅真实 Room 数据，保存失败保留输入与稳定请求，离开页面不取消进行中的保存。沿用 schema 14，新增 12 项真实 SQLite 页面状态测试。公共改动仅为本功能入口与路由接线。

完成标准：手机上可走通「进入页面 → 填出生日期 → 记录／补记 → 更正 → 查看历史」，重开后保留。未填出生日期仍能使用基本功能，主题、返回和开合动画与现有 Bot 一致。

### 步骤五 完成两张历史图表

接入「周期天数分布图」和「时间与年龄趋势图」。第一张显示各天数的次数与比例，第二张在同一区域切换时间与年龄查看方式，并展示趋势及波动范围。支持选择数据点回查起止日期，数据变化后自动刷新，处理全部历史、大字体与手机窄屏。

已实现：共用全部历史／近一年／自选范围；逐天频次；真实时间点与断开的六周期中位数线、年份／年龄汇总及四分位范围；可回查并更正起止记录，按最新版本刷新。2026 年 10 月 26 日按截图将分布卡片精简为标题、坐标轴与柱状图，移除基准比较及说明，所有实际天数直接展示，长零次区间以轴标折叠。复用步骤三、四同一事实快照，后台计算并取消过时结果，沿用 schema 14、版本与依赖。既有图表测试覆盖统计数据到绘图坐标、回查及真实 Room 刷新。

完成标准：两张图与原始记录一一对应；出生日期修改仅改变年龄相关展示，记录变更同时刷新图表和概览；漏记、未完成周期及样本不足按既定规则呈现。

### 步骤六 接入每次独立的 AI 聊天

复用现有 `qwen3.8-flash` 配置和凭据，接入独立会话的新建、多轮补充、历史查看和当前未完成会话恢复。实现记录、更正、删除、备注、查询、提醒配置和相关咨询的意图协议；所需信息通过步骤二、三的本地接口获取。提醒配置先持久保存，其通知执行在步骤七接通，页面和回复如实区分保存与登记状态。

新对话使用新的会话 ID，仅发送本次聊天上下文和按需读取的数据；旧聊天的正文、摘要和待补充问题不自动带入。请求失败保留输入，重复提交复用操作标识；切换或删除会话后，迟到结果按所属会话和版本校验。

已实现：复用默认 qwen3.8-flash、模型设置与安全凭据，接入底部输入、独立新聊天、历史继续／删除、Room 草稿与中断恢复。严格意图协议负责记录、更正、删除、备注、出生日期、查询、提醒规则保存与咨询；本地生成执行回执和统计回复，必要汇总按需提供，批量业务与助手结果原子提交。沿用 schema 14，新增 25 项模型、真实 SQLite 及页面状态专项测试。提醒仅持久保存规则，通知执行仍按步骤七实施。

完成标准：用户可直接说「今天来了」「改成昨天」「今年 28 天有几次」并获得真实结果；单次聊天可继续追问，新聊天没有旧对话上下文，清聊天不删除业务记录。断网时保留手动功能。

### 步骤七 接通两类本地提醒

当前状态：`DAYIMA_LOCAL_REMINDERS_PENDING`。用户在本轮要求先预留标记，后期由联合开发会话处理提醒代码。因此本轮不接入通知、不升级数据库，也不预占 schema 15；现有提醒规则仍只保存在本地，不表示已登记。设计草案、涉及文件和后续验收要求见[本地提醒交接说明](../design/dayima-reminders.md)。

完成准备提醒、缺失记录提醒及其开关、时刻和提前天数，接入本地通知和通知进入大姨妈页面的路径。补齐配置、预测快照、计划版本及交付状态所需的主库迁移，处理记录变更、权限变化、开机恢复和重复触发。

完成标准：页面和对话保存的提醒规则均可在后台执行；无需模型在线，旧规则失效后不触发，重启后恢复，通知状态与实际登记状态一致。

### 步骤八 完成恢复与整体交付

核对草稿和聊天恢复、会话隔离、模型失败重试、统计刷新、通知进入路径，以及侧栏、弹层、图表切换和键盘避让的动画。针对数据迁移、日期边界、统计规则、会话串入、并发重试及提醒失效运行必要自动化验证，回归现有日程与闪念。

运行项目检查与构建：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

构建成功后自动安装到已连接并授权的手机：

```sh
./gradlew :app:installDebug
```

完成标准：分别报告检查、编译和安装结果，提供本轮具体手机操作及预期结果，交由用户测试；若连接或授权阻塞安装，明确说明实际原因和解除方法。

每次完成上述任一应用开发步骤并交付时，都执行相应检查、构建及手机安装，不把安装推迟到步骤八。第八步负责整体验证与交付收尾。手机功能与体验测试由用户完成，助手无需自行操作手机或等待用户测试结束。

## 手机验收场景

以下用于完整功能的后续验收；步骤二的本轮升级回归见[本地记录业务](../design/dayima-business.md#本轮手机验收)。

| 操作 | 预期结果 |
| --- | --- |
| 从侧栏进入大姨妈，点击顶部填写出生日期，保存后再次修改或取消 | 名称及入口一致；保存后更新年龄，取消保留原值，未填写也能查看时间趋势 |
| 对话输入今天开始、补记指定日期、将刚才记录改成昨天 | 各操作定位正确，记录与概览同步刷新，同日不重复，无需严格命令 |
| 目标日期含糊、只说可能要来了或询问原因 | 必要时追问，不生成虚假经期开始记录 |
| 询问一年内 28 天次数与两个时期的变化 | 回复与本地图表、范围和样本数一致，能查看原始日期 |
| 连续保存两条间隔 28 天的开始日期 | 形成 1 个 28 天周期，不把两条日期计算成 2 次；当前未完成周期不参与 |
| 记录跨年、跨生日和闰日，切换统计范围 | 周期不漏算、不重复，年龄按每次开始日计算 |
| 标记漏记跨度、补记中间日期，再更正或删除边界 | 原始数据保留，排除数量可见；相关图表、预测更新，过时跨度标记需要复核 |
| 提供包含极长间隔、稀疏年龄组和被排除阶段的历史 | 尾部数据可查，稀疏组不形成误导汇总，趋势不跨记录断点连接 |
| 断网或模型超时，退出并重开 | 本地记录、图表、预测及已保存提醒可用，输入和待处理状态保留，重试不重复保存 |
| 对话修改提醒，再补记、更正或删除开始日期 | 通知按新规则登记，旧通知失效；关机重开恢复，不重复交付 |
| 在一段聊天里记录日期并追问，再新建聊天询问上次日期 | 同一次聊天可连续补充，新聊天查询业务数据得到正确日期，不携带上一段聊天正文或待补充问题 |
| 在聊天 A 请求处理中新建聊天 B，再返回查看记录 | A 的回复与执行结果归属清楚，不串入 B；已作废请求不得继续执行业务，重试不重复保存 |
| 查看统计后更正出生日期，删除或清空某个聊天并重开 | 年龄重算但周期长度不变，只清对应聊天，经期记录和提醒保留 |
| 切换主题、放大字体、连续开关会话和详情并回到日程／闪念 | 图表标签和操作可读，动画连贯，既有业务与数据保留 |

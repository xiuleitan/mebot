# 首页时间线

2026-10-30：沿用已确认的两列等大卡片设计，本轮接入真实本地业务、处理历史和档案搜索。设计示例只保留在无 ViewModel 的预览及界面测试中，正式首页不混入示例事项。

## 布局

顶部固定侧栏、档案搜索和回到今天按钮；搜索支持选择「语义」或「文字」，提交后直接切换到档案页执行对应查询。语义能力沿用档案模块的配置与失败提示；本地文字查找不依赖模型请求。

主区按明天（眼睛展开）、今天、昨天、前天及具体日期倒序分组。今天和展开的明天使用两列大卡片；昨天及更早的日期使用三列小卡片，标题、圆角及图标相应缩小。同一日期内卡片尺寸一致，有图卡片显示封面和单行标题；无图闪念使用整张卡片多行显示标题，省去占位图标和单行底栏，为已完成横条留位，超长标题按可用空间省略，卡片整体尺寸不变。其他无封面事项继续使用对应 Bot 图标占位。历史日期标题现为12sp的常规灰色文字，居中放在左右两段等长虚线之间，弱化历史分组的视觉权重。今天行最右侧新增眼睛开关，默认关闭，在所有日期统一隐藏已完成卡片；打开后未完成与已完成事项一起显示。只剩隐藏完成项的历史日期暂不显示，记录仍保存在本地。今天旁的「已完成」筛选已移除，只保留右侧眼睛统一控制各日期已完成内容的显示与隐藏。空日期可以略过，今天及主动展开的明天保留空状态；每次再加载三十天历史。

今天行右侧的眼睛默认关闭；打开后，明天的全部事项显示在今天上方，并显示各日期已完成内容，关闭则同时隐藏这两部分，过去未完成事项保留。展开时先插入明天并滚动到顶部，停稳后再展示今天及历史的完成记录；收起时回到今天；列表竖向手势只滚动，不触发明天展示；闪念卡片内的上下手势用于切换闪念。右上角日历回到今天并关闭扩展视图。今天与首个历史日期之间额外增加32dp留白，使卡片底边到历史日期文字的视觉间距约为原来的两倍，其余历史分组间距保持原样。列表与固定输入区域不重叠，内容变化保留位置与透明度动画。

## 事项规则

- 日程包含对应日期的普通、准点和周期实例；未完成事项保留原日期。提前提醒在提醒所属日期出现，同一实例同一天多个提醒合并为一张卡。完成前事务保留已出现的提醒日期，完成后仍能在该日历史查看。
- 闪念每天随机选择一个未完成事项，只占一个普通单张卡片位置，宽高与同排日程卡片一致，保留圆角与柔和阴影，不显示叠层或缩进，右上角使用统一类型标签。多条时在卡片内上下滑动循环切换，单击仍打开原详情；其他区域上下滑动继续滚动首页。只剩一条时显示普通单卡。每日随机种子和当前选择保存在主库，页面重建保留选择；未完成只出现在今天，历史只展示原闪念实际完成日期的完成记录。
- 经期准备和缺失记录提醒按本地预测计划日期展示。正式补记开始日期时，在同一事务完成已出现的提醒，关联到实际记录；未来尚未出现的旧周期提醒直接失效。
- 订阅卡片按提前提醒所属日期展示，手动完成只表示处理提醒，不生成付款事实。取消自动续费后停止待办提醒。已处理历史不因重算丢失。
- 明确删除源任务不会通过首页快照恢复已删除内容。正式任务状态仍由各 Bot 的原始记录负责，首页快照不替代它们。

首页日程卡片直接复用日程页的 `ScheduleCard` 与 `ScheduleDisplayRecord.asEntry()`，今天和明天的封面比例、圆角阴影、标题、底部日期时间、附件数量、标题前的准时闹钟、封面左上的重复标记和已完成状态均采用同一实现；历史三列仅缩小排版尺寸，保留这些信息。附件数量与日程页一样统计原会话全部本地附件，不把封面或其他会话的附件额外计入；附件增删会刷新。提前提醒所在分组与日程实际日期分开，卡片底部始终显示实际发生日期时间。其他 Bot 按日程卡片外框等高占位，闪念使用普通单张外框，保留无图多行标题和剩余空间的正文摘要。此变更仅扩展读取投影，不修改数据库结构、迁移及文件格式。

已完成卡片沿用日程的完成效果：图片逐渐去色、标题区改为完成灰色、图片下方显示「已完成」横条；历史小卡片的横条同步缩小，保留可读字号。所有首页卡片移除独立的完成／恢复按钮及相应触控区，点击卡片任意内容区域只打开对应 Bot 的原详情；首页保留在背景中。完成与恢复统一在详情底部操作，保存期间禁止重复提交，失败保留详情与原状态并提示，成功后自动执行退场动画。补记提醒进入大姨妈原有的经期记录表单，只保存用户填写的真实日期；已补记内容仅作为完成历史展示。详情使用共用遮罩、禁用拖拽关闭，支持系统返回、点击外部和叉号。

## 卡片类型标签（2026-11-01）

首页日程、闪念、大姨妈和订阅卡片统一在右上角贴着卡片顶部显示小标签，文字分别为「日程」「闪念」「大姨妈」「订阅」。标签上沿平直、下角圆润，使用随亮暗主题变化的高不透明度底色与细边框，覆盖图片时保持可读；今天、明天和历史三列均显示，紧凑历史标签相应缩小，已完成卡片保留标签。

无图闪念从第一行显示标题，仅首行右侧避开标签，排到标签位置便换行，后续行使用完整文字宽度。按实际字体和标签尺寸测量换行位置；原有换行保留，极大字体下首行连一个字也容不下时从下一行开始。此换行只影响展示，朗读仍使用原始标题；正文按标题之后的剩余高度显示，为完成横条留位。日程仅通过可选封面标签插槽接入首页，原日程页面不额外增加标签。标签本身不创建操作入口，点击仍打开整张卡片原详情，闪念上下切换沿用原手势。原始记录、主库schema23、迁移和持久文件格式保持不变。

手机检查：查看首页四类卡片，标签应与来源一致且贴住顶部；对比有封面和纯文字闪念，确认文字从首行开始，首行避开标签、后续行恢复完整宽度。打开眼睛查看明天及已完成事项，再滚动到历史三列，检查标签与闹钟／重复标记、完成横条各自清楚可见。在亮暗主题和放大字体下检查边界；点击标签位置应打开原详情，上下切换闪念仍应正常。

## 输入入口边界

底部直接复用日程的 `BotComposerWorkspace`、`BotComposerInput`、`DeviceMediaPanel` 和系统选择器；圆角、字号、输入高度、键盘发送、加号开合、最近照片、相机／相册／文件及待发送附件排版保持一致。首页输入不显示额外占位文案。图片和文件可与文字混合选择，附件支持预览、移除及继续添加；最近照片的已选顺序在重开后保留。

首页草稿独立于各 Bot：文字写入 Room，原始附件复用 `LocalMediaStore` 复制到本地持久文件，去重元数据与草稿关联在同一事务内完成；移除时保留其他业务仍引用的原图。输入自动保存，失败保留未保存文字并提供重试，系统选择器与拍照返回可在页面重建后继续处理。追加 23→24 迁移，仅增加 `home_composer_drafts`、`home_composer_attachments` 两表，保留既有70张表与1→23迁移。

首页发送前根据文字调用 `decision-model-preview`，从最后一次文字变化起连续2秒未变化才判断一次，持续编辑时重新计时、文字不变不重复判断，只发送本次文本与固定五个Bot选项；去掉other／未归类，正常响应直接取五项中的最高概率，不设置信度门槛；在输入文本开头插入彩色 `@名称`，点击标记打开五个Bot列表。退格将标记整块删除，正文保留；仅修改标记不自动补回，正文变化后即使此前手动选择过，也在停满2秒后重新判断。发送必须同时具备有效的开头标记与非空正文，名称错误、无标记、判断中、正在导入或交接时不能按钮发送或键盘发送。标记不传给决策模型及目标Bot，自动插入／更换时保留正文光标和中文组合输入位置。决策失败或离线时保留输入，允许手动选择；不按本地猜测伪装模型结果。

分类规则先识别明确的经期、订阅管理和建档业务，再区分普通行动的执行时间：有今天、明天、今晚、下周或周期安排的普通事项归日程；无执行时间的普通待办、想法归闪念。给模型的简短总提示与五项正向业务描述共同说明这个顺序，保留闲鱼查看、整理房间、时间背景和银行卡行动等必要对照；采用真实接口测试后的英文判定说明，界面名称和持久ID保持原样；具体语句验收见[首页路由方案](../plans/2026-11-01-home-bot-routing.md)。

发送后，首页文字、可靠本地附件与原Bot的独立任务在主库事务内交接，成功后才清空首页草稿；持久回执避免重复点击或恢复后重复写入。日程、大姨妈、订阅管理和档案直接承载原输入与聊天组件，后续追问属于该任务，决策模型不再参与。闪念走原仓库直接保存并排队生成标题，保存后留在首页，不打开聊天。每条消息只路由一个Bot。原Bot不接受的附件会明确提示并保留原输入；不丢弃附件来强行发送。

首页使用独立的新任务，不覆盖原Bot未发送的草稿。日程原有的唯一创建草稿清理排除已交接的首页任务；未完成会话保留。档案继续使用原加密附件格式，从首页的可靠本地副本复制，失败可重试；清理只释放无任何业务引用的原图。当前会话的关闭沿用原返回、遮罩和叉号规则及退场动画。

路由配置位于模型设置，模型ID固定为 `decision-model-preview`，配置专用HTTPS System One地址并沿用应用安全存储中的百炼API Key。本机预览的空间地址仅从已忽略的 `local.properties` 注入默认值，正式项目中不硬编码个人空间ID，不保存明文密钥。追加24→25迁移：`home_routing_settings`、`home_dispatches`，冻结原72张表与1→24迁移。

## 原 Bot 详情复用（2026-10-30）

首页不再渲染通用的“打开某 Bot／完成”详情。按来源直接使用各 Bot 的原 Route，以仅展示详情的方式打开，同一套详情、编辑、删除确认、附件预览、写入校验及成功／失败反馈同时服务两个入口：

- 日程直接使用 `ScheduleRoute` → `ScheduleScreen` → `ScheduleSheet`，宽高、标题、日期时间、附件数量、图片排版及删除／编辑／完成按钮完全共用。编辑进入原日程会话，删除继续区分本次／整个周期，支持停止重复。
- 闪念直接使用 `FlashnoteRoute` → `FlashnoteScreen` → `FlashnoteDetailSheet`，沿用完整正文、图片／文件、标题编辑、草稿和完成／恢复流程。
- 订阅直接使用 `SubscriptionsRoute` → `SubscriptionDetailSheet`、原编辑表单、聊天、图片预览和删除确认。提醒的完成／恢复放在共用详情中，两个入口使用同一实现；只确认提醒处理，不登记付款。打开历史卡片时保留其提醒 ID，不替换为另一周期。
- 大姨妈直接使用 `DayimaRoute` → `DayimaSheetHost`，保留原详情、删除、编辑、图片和记录表单。准备提醒与补记入口放在原详情中；补记保存由大姨妈原本的事务完成提醒历史，已补记卡片打开实际关联的新经期记录，保持原提醒日期。

详情关闭后留在首页原位置；编辑和聊天沿用原 Bot 的完整流程。原 Bot 正文和附件由各自的数据层读取，不另做简化展示。导航过渡完成后再挂载来源详情，避免离开的 Bot 与首页同时占用同一 ViewModel 和附件会话。关闭借用流程时，原 Bot 的详情、编辑和内部弹层均先完成退场。

## 录像中的逐行停顿修复（2026-11-01）

用户的3.24秒录像确认，单独展开明天时也会几次移动、停住、再移动。按同样的三张明天卡片、混合整行标题、两列卡片、寄语和三列历史构造原生回归，旧实现能复现中途连续11个16ms测试帧的停顿；仅将完成历史延后不能消除这个问题。

原因是`LazyGridState.animateScrollToItem(0)`按可见网格行估算目标距离，当前行高度与跨度差异很大。目标尚未进入视口时会分段接近，到目标可见后再对齐，造成录像中的反复减速／再启动。本次眼睛展开不再使用这种寻址方式：

- 按现有六格网格的实际左右列宽，复用`ScheduleCardMetrics`计算每行卡片高度；标题及空状态直接按原文字样式、当前字体缩放和内容宽度测量。两张同排卡片使用同一行起点，末尾单张和空明天均单独处理。
- 将这些行起点换算为相对于顶部的像素位置，由当前可见项及其像素偏移取得完整移动距离；以一次360ms缓动连续滚动到顶。只允许末尾整数像素舍入对齐，不在每一行重新启动弹簧动画。系统关闭动画时继续立即到位，手势接管仍能取消本段滚动。
- 远处历史返回顶部继续使用原列表寻址；明天展开使用已知的局部区域。分步展示、眼睛过滤、记录归属、图片读取和原始数据不变；未修改Room/schema23或迁移。

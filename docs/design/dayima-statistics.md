# 大姨妈周期统计与预测

开发步骤三，提供本地计算、查询和订阅接口，供第四步主界面、第五步两张图以及后续 AI 查询共用。计算从同一 Room 事实快照读取开始日期、出生日期、跨度标记及数据版本，在后台线程执行；主库继续使用 main 基线的 schema 14。

## 查询入口

通过现有 `AppContainer.dayima` 访问：

| 接口 | 返回内容 |
| --- | --- |
| `statistics(range)` | 一个统计范围内的周期、分布、基准比较、趋势和分组，以及当前未完成周期与最新预测 |
| `compareStatistics(first, second)` | 从同一快照比较两个日期范围，返回各自样本数、分布及中位数差值 |
| `observeStatistics(range)` | 订阅成功提交和本地日期变化，重新返回同版本事实计算出的结果 |

`DayimaStatisticsCalculator` 可对指定快照和评估日期执行纯计算。每份结果携带 `dataVersion`、`asOfDate` 和统计范围，查询不会修改业务记录。订阅在被收集时运行，取消后释放；日期检查最多每分钟一次，日期不变时不重新查询和计算，跨午夜会刷新当前周期天数。手机时区变化不会移动已保存的日历日期。

本轮新增代码局限于大姨妈数据层、测试和功能文档。公共导航、数据库结构及应用版本继续沿用同步的 main 基线；按用户最新要求，health 分支独立构建并安装供查看，整体审核合并在用户需要时进行。

## 完整周期与日期范围

完整周期是相邻两个实际开始日期之间的日期差。例如 1 月 1 日和 1 月 29 日开始，形成一个 28 天周期。先按日期排列全部已发生记录并形成周期，再按周期开始日筛选范围。范围最后一条的下一次开始即使在范围之外，仍用于确定这个已经结束的周期。

当前最后一次开始到评估日期的间隔返回为 `currentCycle.daysSinceStart`，开始当天为 0；它不进入完整周期频次，也不因时间经过被补造成多个周期。评估日期之后的已存日期保留在原数据中，计算时跳过并返回数量；它们不作为已发生记录关闭当前周期。

Room 保证开始日期唯一；纯计算接口遇到重复日期或 ID 时拒绝歧义输入。较长或较短的未标记间隔按实际数据保留，不以固定医学阈值自动删去、拆分或判断异常。

## 漏记与待复核

| 周期状态 | 统计及预测处理 |
| --- | --- |
| `ELIGIBLE` | 进入普通分布、分组、滚动统计和连续预测样本 |
| `MISSING_RECORDS` | 有效漏记标记，单独计数并排除 |
| `SPECIAL_PHASE` | 有效特殊阶段标记，单独计数并排除 |
| `PENDING_REVIEW` | 当前相邻端点对应待复核或失效标记，单独计数，等待复核后再参与普通统计 |

完整周期总数包含这些状态；有效数、明确排除数和待复核周期数分别返回。标记的有效性与记录管理共用同一个校验函数，检查持久待复核状态、端点是否存在且相邻、日期及版本是否一致。

补记导致旧标记的端点不再相邻时，旧标记不会被套用到新形成的两个子周期。新子周期依据当前实际记录及各自标记统计，旧标记仍计入待复核提示。待复核标记数量与待复核周期数量分别报告，因为有些旧标记已不能对应一个当前周期。标记提示按当前起点日期归入查询范围，起点已删除时使用原快照起点日期。

## 分布与两种基准

频次仅使用有效完整周期，返回实际出现的每种天数、次数、比例及对应周期起点 ID，供图表点击回查。极长间隔只增加一个实际出现的分组，不生成巨大连续天数数组，也不截掉尾部数据。

固定 28 天与当前范围内的个人中位数分别返回短于、相同、长于基准的数量及比例。个人中位数可以为半天，此时整数周期可能没有“相同”样本。没有样本时，中位数和比例为空，数量为 0。

总体分布返回中位数、最短／最长值和居中一半的范围。四分位数统一使用位置 `(n−1)×p` 的线性插值，和前期图表示意的计算口径一致。它们描述历史分布，不是正常范围或预测置信区间。

## 时间与年龄趋势

时间趋势为每个周期提供起点日期、天数、状态和连续段 ID。最近六个连续有效周期齐备后才显示滚动中位数，并返回这六个周期的 ID；明确排除和待复核周期会清空窗口并断开连续段。筛选某段历史时保留全历史的滚动口径，首个可见点可能使用范围前的历史，其来源 ID 可回查。

年龄按周期开始日与出生日期计算实际周岁。跨生日的周期按开始时年龄分组；闰日生日遵循 `java.time.Period` 的历法计算，非闰年 2 月 28 日尚未完成下一个整年，3 月 1 日增长周岁。出生日期缺失、晚于某次开始或晚于评估日期时，相应年龄为空；周期天数、频次及时间趋势仍可使用。

按年份和周岁分别分组，保留样本 ID 和数量。每组至少三个有效周期才返回中位数与四分位范围，少于三个时供界面展示原始点和数量。`hasEnoughAgeHistory` 要求所选有效年龄历史覆盖至少 365 天，且至少两个年龄组分别有三个样本；这个标识只供决定是否展开年龄变化描述，不代表医学结论。

两个范围的比较使用同一快照。每侧至少三个有效周期才返回“第二段中位数减第一段中位数”，否则仅给出各自数量和分布；它不自动推断变化原因。

## 下一次日期预测

预测使用全部已发生历史的最新连续有效段，与图表筛选范围无关。沿用旧版规则：最多六个间隔，权重依次为 1 到样本数，越近越高；加权平均四舍五入到整数天，加入最新开始日期得到预计日期。只有一个间隔时范围为前后 2 天；多个间隔按最大偏差向上取整，并限制到前后 2～7 天。

最新周期被排除或待复核时，不能越过断点借用较早历史。最新一段至少形成一个有效间隔才预测；无记录、连续样本不足及日期超出历法范围分别返回明确状态。

预测窗口已经过去时仅返回 `rangeHasEnded`，不把预计日期自动推向下个月，不补造已经发生的周期，也不据此断言身体状态。预测输入间隔及对应周期 ID 与日期结果一同返回，后续登记提醒时可据此保存预测快照。

## 验证与手机交付

新增 32 项专项用例：26 项纯计算测试和 6 项真实 SQLite 业务订阅测试，覆盖跨年、闰日生日、空样本、未来记录、分组门槛、四分位插值、两种基准、漏记与待复核、趋势断点、六次加权预测、日期溢出、编辑删除刷新和跨午夜订阅刷新。

功能分支执行项目单元测试、lint 和 Debug 构建，提交后安装本分支 APK 供用户查看；后续用户要求看整体效果时再由集成会话审核合并。本轮计算结果通过自动化验证，图表和大姨妈页面在后续步骤接入。

同步最新公共修复后的分支验证结果：398 项全量测试通过（包含上述 32 项新增用例），lint 无错误，Debug APK 编译成功。安装来源应记录分支、提交、APK 摘要与设备结果，保留原有手机数据。

分支安装后用户回归：

1. 打开日程与闪念并重开应用：既有记录、完成状态和原有入口保留。
2. 打开已有详情、图片、附件及聊天：内容完整，原有操作可用。
3. 查看主题、模型和铃声配置：配置保留；本轮尚无可点击的大姨妈统计界面。

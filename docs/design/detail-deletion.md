# 各 Bot 详情删除约定

按 2026-10-28 的联合开发要求，已保存记录的详情统一使用日程的删除方式：操作区的删除按钮位于最左侧，浅红底、深红字，触控高度至少 48 dp。点击只请求确认，确认后才执行原有本地删除。

2026-10-29 按钮形状核对：同一操作栏内的按钮保持等宽、等高，形状、内边距和文字基线一致。日程、闪念、档案和大姨妈详情沿用同排的 16 dp 圆角；订阅详情的删除、编辑、聊天共用主题默认胶囊形状和内边距，避免混用两套形状。大姨妈备注编辑中的删除、取消、保存同样使用默认胶囊形状和一致内边距，统一至少 50 dp 高；文字换行时整排一起增高。

| Bot | 详情底部从左到右 | 确认时保留的业务含义 |
| --- | --- | --- |
| 日程 | 删除／编辑／完成（或已完成） | 普通日程删除记录及对应会话；周期日程先选仅本次或整个周期，再明确确认范围 |
| 闪念 | 删除／编辑／完成（或恢复） | 删除当前版本的闪念及专属附件，共用附件与完成统计沿用原有保留规则 |
| 订阅 | 删除／编辑／聊天 | 从持续列表移除，聊天、图片和消费数据保留，可从已结束列表找回；不会取消服务商续费 |
| 档案 | 删除档案／编辑档案 | 只移除卡片，原会话历史和附件保留 |
| 大姨妈 | 删除／编辑 | 删除指定开始记录，相邻周期重算，关联备注保留；备注及周期标记分别使用其既有目标和说明 |

详情操作栏保持在正文滚动区之外。确认框背景与文字跟随应用主题，正文包含当前目标或日期以及真实删除范围；底部等宽排列「取消／确认」，左侧描边取消，右侧浅红确认。取消、系统返回和点击确认框外部只收起确认框，原详情和记录保留。执行过程中禁用确认与取消，避免重复提交；删除失败继续使用各 Bot 原有错误提示与重试流程。

共享实现位于 `ui/common/DetailDeleteActions.kt`，只负责按钮和确认框呈现。各 Bot 继续持有目标、确认状态、忙碌状态及实际执行回调，不引入新的业务删除服务，不修改主库、迁移、附件格式和索引规则。当前手机已预览的大姨妈详情右上角关闭按钮位置继续保留。

## 手机验收

1. 分别打开五个 Bot 的一条测试记录，确认删除位于操作栏最左侧；滚动长正文，删除与其他操作始终可见。
2. 点击删除，确认原记录仍在，确认框显示正确标题或日期；分别点击取消、按系统返回、点框外，详情仍打开且记录不消失。
3. 再次点击删除并确认，只处理当前记录且不重复提交。闪念删除后退出详情；订阅可在已结束列表找回；档案原会话和附件保留；大姨妈关联备注保留、周期统计更新。
4. 日程额外检查普通日程、周期仅本次和整个周期：确认框准确区分范围，取消不改变其他日期；仅删除本次后其他日期继续可见。
5. 切换亮暗主题、放大系统字体，检查删除红色、取消描边、确认文字及触控区域可辨认；编辑、完成／恢复、聊天和右上角关闭仍可使用。

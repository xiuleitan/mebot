# 闪念本地业务操作

业务基础版本：0.16.3。开发步骤二在共用主库中实现新建、编辑、删除、完成、恢复及草稿保存。初期使用 schema 9，0.19.0 通过保留数据的 9→10 迁移接入媒体关联。

业务由 `FlashnoteRepository` 执行，通过 `AppContainer.flashnotes` 提供统一入口。0.18.0 已接入 ViewModel、真实新建、筛选、全文详情及编辑／取消／删除／完成／恢复按钮，详见 [闪念页面与真实记录](flashnote-ui.md)。编辑与新建草稿独立，失败保留内容和提交快照；两类页面写入共用串行队列。

## 操作入口

| 入口 | 行为 |
| --- | --- |
| `openCreation` | 恢复现有新建草稿，没有草稿时生成新 UUID 并保存空草稿 |
| `openEditing` | 读取事项并恢复或建立编辑草稿，保存原记录版本；事项不存在时拒绝打开 |
| `saveInput` | 按草稿版本条件保存标题和正文，内容相同的重试不增加版本，不重新插入已消失的草稿 |
| `save` | 使用落库草稿快照提交；根据编辑目标执行新建或编辑，同时清理对应草稿 |
| `complete`、`restore` | 指定目标状态；重复请求保持状态及时间不变，恢复时清空完成时间 |
| `delete` | 按记录版本删除，级联清理相关编辑草稿；重复删除返回已不存在，不影响其他事项和新建草稿 |
| `discardDraft` | 按草稿版本取消，不修改原事项，也不清理较新的输入 |
| `attach`、`removeAttachment` | 修改独立草稿的附件关联与签名，递增草稿版本；不立即改动正式记录 |
| 查询及订阅 | 按 ID 读取事项／草稿，按状态查询列表，支持订阅数据库变化 |

新增和编辑要求正文非空或至少包含一份附件，保留完整正文及换行。只有图片时使用「图片闪念」作为默认标题，仅文件时默认使用首个文件名。未提供标题时，先使用第一条非空正文行作为本地标题，保存成功后由独立后台任务生成 8 字以内的 AI 标题；AI 失败不回滚保存。明确提供的手动标题沿用既有规则，仅清理两端空白。AI 不改写原始正文与附件。

正式事项的创建时间在首次成功提交时生成。编辑只更新标题、正文、修改时间和版本；状态变化只更新状态、完成时间、修改时间和版本，均不修改创建时间。未完成和已完成都按 `createdAt ASC, id ASC` 查询。

## 重试与事务

同一次提交始终使用同一份草稿快照和标识。新建草稿的 UUID 同时作为正式事项 ID，不得在每次点击保存时重新建立草稿。相同文字通过另一份新草稿主动保存时，可以成为另一件事项。

正式记录写入和草稿清理在一个 Room 事务中完成。任一步失败都会回滚，保留草稿供重试，不报告保存成功。

已清理草稿的重试只核对现有事项：记录仍存在且标题、正文匹配时返回当前记录，不重写时间和版本；后续内容已改变则报告冲突；记录已删除时拒绝旧请求，不重新创建。编辑有版本冲突时保留未提交草稿，不覆盖较新的记录。

附件本体通过 `FlashnoteAttachmentRepository` 复制到共享持久媒体存储，文件发布、元数据及草稿关联一起提交。正式保存同时核对附件签名；编辑仅修改附件也会递增正式版本，不修改创建时间或完成状态。原提交的重试只能接受相同文字及同一附件顺序，不能把后来改过附件的记录误报为本次成功。

0.20.0 将状态和统计一起提交：完成登记手机当地日期，恢复删除该项有效完成日；删除已完成事项将数量转入不包含事项 ID 或内容的按日汇总。重复完成与删除不增加历史次数，失败整笔回滚。历史按月汇总，编辑内容不移动完成日期。

完成／恢复使用明确的目标状态，避免重复点击将状态再次翻转。已经处于目标状态时返回原记录；需要改变状态时校验版本，首次完成时间不会被重试刷新。旧的完成请求不能撤销较新的恢复结果。

DAO 的内容更新、状态更新和删除均支持版本条件。草稿自动保存只更新仍存在的草稿，不使用重新插入或覆盖式写入；取消或删除后的迟到输入不能使数据复活。

## 验证

`FlashnoteRepositoryTest` 在开发机使用真实 SQLite，包含 18 项专项测试，覆盖：

- 创建时刻、原文及默认标题；空正文失败时保留草稿。
- 同草稿 12 个并发提交、数据库重开后重试及后续新草稿保留。
- 两份独立草稿可保存相同文字，旧提交不能覆盖后来的编辑。
- 编辑已完成事项保留原状态、完成时间和创建时间。
- 乱序完成、恢复及编辑后，两个列表仍最旧在前。
- 完成／恢复重试不改时间和版本，旧状态请求不能反转新结果。
- 草稿和事项版本冲突、取消、删除，以及迟到请求不覆盖或重建数据。
- 使用 SQLite 触发器模拟草稿清理失败，验证新建和编辑的整笔事务回滚。
- 重开恢复输入、UUID 冲突及未持久化快照校验。

继续运行现有存储及升级迁移测试，确保日程、附件、会话、配置和提醒相关能力保留。

## 手机验收

1. 覆盖安装后进入日程，查看已有日期、卡片、会话、图片和文件附件：原内容及完成状态应保留，无启动或数据库错误。
2. 对一项已有日程完成后恢复，再重开应用；检查日程状态及“通知提醒”的铃声配置仍正常。
3. 进入闪念并输入多行文字，点击保存：应产生一张真实本地卡片，成功后输入清空，创建时间与正文重开后保留。
4. 切换未完成／已完成并查看卡片全文；未发送输入在离开页面后可恢复。编辑、取消、删除、完成／恢复均可在详情操作，卡片另有独立完成／恢复按钮；完整页面验收见 [闪念 UI](flashnote-ui.md#手机验收)。

## AI 标题

`titleSnapshot` 在事务中读取同版本记录及附件，存在编辑草稿时不启动模型请求。`applyGeneratedTitle` 重新核对完整记录、附件快照和编辑草稿，只通过标题专用 SQL 条件更新标题、修改时间和版本。模型只可返回一个 `title` 字段，1–8 个 Unicode 字符，正文、状态、附件或其他字段输出均被拒绝。状态变化、编辑、附件变化及删除会使旧快照失效。

WorkManager 任务按记录 ID 与版本唯一登记，队列中不存正文、图片、密钥。新建保存后自动登记，已有记录按详情按钮单条触发，普通编辑不自动覆盖手动标题。线上模型与图片处理失败只影响标题任务；本地查看、编辑、删除、完成、恢复及下一条输入继续可用。重试标题不再提交草稿，不重复插入闪念。

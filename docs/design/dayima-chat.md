# 大姨妈独立 AI 聊天

2026-10-29：所有底部弹层统一禁用拖动和下滑关闭，保留正文滚动、系统返回、遮罩与右上角叉号，见[底部弹层约定](bottom-sheets.md)。

开发步骤六，在大姨妈主界面接入每次独立保存的 AI 聊天。复用现有语言模型设置、HTTPS 传输和 Android Keystore 凭据，默认 `qwen3.8-flash`。聊天、草稿、请求状态与业务数据仍保存在应用主库。步骤六最初沿用 schema 14；2026 年 10 月 28 日新增本地图片附件，使用已协调的 18→19 保留数据迁移，见[图片方案](dayima-images.md)。没有新增云端业务服务或依赖。

## 页面与会话

主界面直接复用日程的 `BotComposerWorkspace`，输入栏、媒体面板、浮窗尺寸及开合动画均使用同一个组件。每次从空白输入处理一件事，例如「今天是第一天」「昨天开始」「补记上周三开始」；发送后收起键盘并打开本次任务浮窗，追问、连续更正及失败重试在本次任务内完成。页面不显示「展开聊天」按钮或长期聊天工具栏。

关闭浮窗且输入及待发图片均为空时，等待处理结束后打开新的空白会话，下一次请求不沿用旧任务的消息或目标。若仍有未发送的文字或图片，继续保留这份草稿。浮窗的清空按钮使用现有删除当前聊天的确认流程，正式记录、正文与已关联记录的图片不受影响。

加号保持与日程一致的外观，点击收起键盘并平滑展开共用媒体选择面板，可从最近图片、系统相册或相机添加照片。图片复制到应用本地并随所属聊天草稿恢复，发送后可添加到明确的开始记录，在详情中预览；仅图或目标含糊时先追问。文件入口暂时提示「暂时不支持文件，请选择图片」。当前文字保留，聚焦输入或发送会收起面板。界面适配仅在大姨妈模块内实现，不修改其他 Bot 或公共媒体组件的行为。

每次任务使用独立 ID，旧消息和草稿仍保存在 Room；主流程以空白输入和本次任务浮窗为入口。单次任务较早的消息按每批 40 条加载。删除只清除该会话的消息、操作状态及草稿，不删除已经保存的经期日期、备注、记录图片、出生日期、提醒规则或业务事务回执。

当前输入通过 Room 草稿保存，短暂防抖合并键入，发送、切换和离开页面时保存；SavedStateHandle 仅保留尚未落库的短期恢复信息与所属会话、版本。发生草稿冲突时保留输入，由用户选择保留并重试，不静默覆盖另一份草稿。

新建／切换／删除聊天会取消本地旧分析并使旧请求失效。进程中断留下的未完成请求恢复后显示可重试，不自动重发收费请求。已经持久化成功的请求不再调用模型，也不会因重试重复执行业务。

## 本地执行协议

模型返回严格 JSON，只能选择追问、咨询回复、本地查询、受限的数据读取或明确的业务操作；未知字段、类型不符、无效日期及截断结果均拒绝执行。模型不发送 SQL、不生成数据库 ID、不直接写库，也不能用一段回复代替保存回执。

| 需求 | 处理 |
| --- | --- |
| 发送照片或给某天补充照片 | 只作本地附件，明确唯一目标后与业务结果一并保存；图片内容、文件名和本地路径不发送给模型 |
| 今天来了、补记某天开始并加备注 | 记录准确开始日期及可选备注，同日不重复新增 |
| 刚才记错，是昨天／将指定日期更正 | 引用本聊天唯一的目标或明确日期，按真实 ID、版本更正；目标含糊则追问 |
| 删除指定开始记录 | 核对明确删除意图和目标；关联备注保留为独立备注 |
| 独立记录情况、保存或移除出生日期 | 按用户明确要求保存，不把咨询或预计情况当作实际开始 |
| 上次何时、历史日期、备注、天数次数与占比 | 本地读取事实并组织回复，数字使用现有统计接口，不让模型自行数日期 |
| 两段时期是否变化、按年龄查看 | 本地对比样本数、中位数及分布，稀疏样本不给出整体变化结论 |
| 调整提醒开关、时刻、提前天数 | 保存现有提醒配置；明确说明通知执行仍待步骤七接通，当前不会发出这两类提醒 |
| 咨询或普通交流 | 回复标为「AI 咨询」；需要个人背景时按需读取汇总或继续询问，不能据周期数字直接诊断 |

同一请求中的明确操作先全部校验，再在一个事务内提交正式业务、去重回执、助手结果及请求完成状态。日期冲突、未来实际日期、目标不存在、目标版本变化或任一写入失败时，不出现部分保存却报告全部成功。跨午夜或重开后重试，相对日期仍锚定原消息发送时的日期与时区。

一次在途请求绑定会话、用户消息和独立 attempt ID。执行前再次核对会话仍有效、请求仍为当前请求、业务版本和提醒版本未变化；迟到结果不能写入另一聊天、重建已删除记录或覆盖已变化记录。需要补充的问题持久保存；用户下一条回复只承接本会话的问题，新的否定删除要求优先于之前的删除意图。

## 上下文与联网范围

只携带当前会话最近的完整消息，最多 30 条／24,000 字，并明确告知模型历史是否截取。其他会话、日程和闪念聊天不进入上下文。本次聊天的最近明确目标可供连续更正使用；没有唯一目标时不回退为全库最近一条来猜测操作。

普通记录不上传全部历史。咨询确需背景时，只允许按需读取最近记录、统计汇总或提醒规则，最多三轮；出生日期不进入读取结果，年龄问题提供年龄分组，备注正文与全量原始日期列表不作为模型工具结果。手机上已经展示的本地查询／执行回复在后续模型上下文中替换为简短占位说明，所需数字重新按需读取，避免把一整份历史随聊天反复发送。

API Key 仅由现有安全凭据层提供给 HTTPS Authorization，不进入请求正文、聊天消息、普通日志或测试产物。没有真实服务端调用的自动化测试使用模拟模型及虚拟凭据，不读取用户手机记录或生产 Key。缺少配置、鉴权／额度、网络／超时、限流、响应格式、本地保存、记录变化和中断分别映射为可辨识状态。

本轮运行 `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug`：全量 451 项测试通过，无失败或跳过；Lint 无错误，保留 11 项既有警告，本次聊天文件无告警；Debug 构建成功。期间既有日程预加载用例发生一次时序失败，单独复核及完整回归重跑均通过，未修改日程实现或测试。自动化测试使用模拟模型，真实模型语义与手机交互按以下步骤验收。

2026 年 10 月 26 日输入栏样式对齐后的检查：全量 504 项测试无失败、错误或跳过，Lint 无错误、14 项既有警告，Debug 构建成功。沿用 0.21.7（86）、主库 schema 14，草稿保存、会话隔离与模型执行协议保持现有实现；图像和文件仅显示暂不支持提示。

手机功能与真实模型语义由用户验收：

0. 对照日程底部输入栏：圆角、底色、圆形按钮与尺寸一致。输入多行文字时最多显示三行并平滑增高；点击加号展开图片面板，支持相册和拍照，取消不丢文字。检查草稿重开、只发图后补日期、同日补图、聊天删除后的记录图片保留，详见[图片验收](dayima-images.md)。聚焦只编辑输入；空白任务不显示展开按钮，有消息或处理中任务收起后可重新打开；发送才打开任务浮窗，关闭后的空白输入开始下一次独立任务。
1. 在「模型与 API」确认语言模型和 Key，进入大姨妈，在底部发送「今天来了，也记一下腰酸」。按钮和键盘发送均收起键盘并展开聊天；应出现本地保存结果，主界面只有一条对应开始记录和一条备注；同日再次记录不重复增加日期。
2. 同一聊天继续「刚才记错了，是昨天」，应更正同一条记录并更新概览、图表。关闭本次浮窗，回到空白输入后只说「改成昨天」应追问目标，不携带上一聊天消息或猜全库最近记录。
3. 询问「今年刚好 28 天有几次、占多少」「上次是什么时候」并与本地图表核对。只有一条开始记录时不虚构完整周期，漏记及待复核数量如实说明。身体咨询显示 AI 咨询，不自动写开始日期。
4. 关闭网络后发送，查看明确错误与保留的用户消息；恢复网络后点击本次重试，不重复新增记录或备注。断网期间历史浏览、已有记录的更正与备注编辑、两张图及预测仍可用。
5. 完成一次记录后关闭浮窗，确认回到空白输入，下一次发送不带上次消息及隐含目标。若关闭时有未发送文字或图片，草稿仍保留；退出重开也应恢复。清空当前任务后，迟到回复不得继续执行旧业务。
6. 删除一个有保存结果的聊天，确认只删除消息和草稿，正式日期、备注、生日和提醒配置仍保留。连续开合任务浮窗、键盘和记录详情，检查大字体、主题、返回及日程／闪念回归。
7. 对话保存「提前两天晚上八点提醒，关闭缺失记录提醒」，核对回复给出真实配置，并说明后台根据可用预测和通知权限执行；保存规则不等于通知已经登记或投递。

# 大姨妈本地数据基础

步骤一交付版本：0.20.0，主库通过保留数据的 11→12 迁移新增大姨妈存储。结构化数据继续保存在现有 `mebot.db`，没有另建数据库。步骤二已进一步接入 [本地记录业务](dayima-business.md)，当前 schema 为 14，包含 [13→14 兼容恢复](database-recovery.md)；下文保留第一步的交付说明。

本轮提供实体、DAO、索引和应用数据入口。业务参数校验、记录执行、统计、界面、AI 调用和通知调度在后续步骤接入；当前侧栏尚无大姨妈入口，也不写入任何示例经期数据。

## 数据与关联

| 表 | 保存内容与约束 |
| --- | --- |
| `dayima_profile` | 单份出生日期资料及版本，未填写时可为空 |
| `dayima_periods` | 每次开始日期、创建与修改时间、版本；开始日期唯一，历史按实际日期排序 |
| `dayima_notes` | 发生日期、文字及可选经期关联；删除经期只解除关联，文字保留 |
| `dayima_span_markers` | 漏记／特殊阶段的两个端点，以及标记当时的日期、记录版本和说明 |
| `dayima_chat_sessions` | 各次独立聊天的标题、状态、时间和版本 |
| `dayima_chat_messages` | 按会话保存消息；会话内序号唯一，支持按序号分页查询 |
| `dayima_chat_drafts` | 各会话各自的未发送文字及草稿版本 |
| `dayima_chat_operations` | 每条请求的处理状态、尝试标识、待补充问题及执行回执；同一请求只保留一条操作状态 |
| `dayima_reminder_settings` | 两类提醒开关、分钟级时刻、提前天数及配置版本；仅保存设置，不登记通知 |

出生日期、经期日期和备注发生日期使用主库既有的 `LocalDate` 与 epoch day 转换；提醒时刻使用分钟级 `LocalTime` 转换。日期不通过午夜时间戳转换，避免时区变化移动日历日期。新建或升级数据库时，这九张表为空，不自动生成资料、聊天、记录或提醒配置。

经期、备注和提醒配置不依赖聊天存在。删除一个聊天会级联清理它的消息、草稿和操作状态，其他会话及正式业务记录保留。请求操作同时引用消息 ID 与会话 ID，复合外键拒绝把一个会话的请求归入另一个会话。

跨度标记保留当时的端点日期和版本。修改经期日期不会跟随改写这些快照；端点删除后保留标记并将相应引用置空，供后续复核。步骤二、三的业务层还需检查端点是否仍相邻、日期和版本是否匹配，才能应用排除规则。

## DAO 与应用入口

`MebotDatabase.dayimaDao()` 提供读写原语，`AppContainer.dayimaStorage` 复用同一个主库实例提供该入口。后续 Repository 在这层之上协调业务校验和跨表事务，页面不直接执行 DAO 写入。

插入统一使用 `ABORT`，重复日期或 ID 会报告冲突，不使用 `REPLACE` 覆盖原记录。编辑、删除和草稿保存通过预期 revision 条件执行，返回受影响行数；旧版本更新不能覆盖较新的内容，也不能重新插入已删除会话的草稿。

会话查询、消息分页、待补充问题和操作状态均按会话 ID 读取。本轮没有跨聊天摘要或长期记忆。操作的 `resultJson` 仅是执行回执，经期事实和后续统计仍从正式业务表读取。

## 迁移与验证

保留完整迁移链，增加 `MIGRATION_11_12` 并导出 schema 12；schema 11 作为升级前快照保留。迁移只创建新表及索引，不改写原有 26 张业务表，不访问媒体或铃声文件。

`DayimaStorageTest` 使用开发机上的真实 SQLite，10 项专项测试覆盖：

- 新库为空，日期、配置、备注、跨度、聊天、草稿和处理状态重开后保留。
- 同日或同 ID 冲突不覆盖记录及关联备注；日期范围、历史排序和消息分页准确。
- 各会话的序号、追问和操作隔离，跨会话关联及孤立子记录被外键拒绝。
- 删除聊天只清本次会话；删除经期保留备注和跨度快照，迟到草稿不能恢复已删除会话。
- 资料、草稿、提醒和操作的版本条件更新，以及跨表写入失败时整笔事务回滚。
- 从实际 schema 11 建库，填充全部旧业务表后升级，逐项核对所有旧行、表及索引定义，以及原图、附件、铃声文件；通过 Room schema 与外键校验。

既有闪念迁移测试同步使用 schema 12 作为升级目标，继续验证从更早版本升级的数据保留。应用开发交付运行单元测试、lint、Debug APK 构建，并安装到已连接且授权的手机。

本轮结果：全项目 323 项单元测试通过（包含上述 10 项专项测试），lint 无错误，Debug APK 构建成功。0.20.0（versionCode 71）已覆盖安装到已连接的 PMW110 手机，安装结果为 `Installed on 1 device`；手机包信息已确认该版本。手机端功能与数据升级回归由用户按下方清单验收。

## 本轮手机验收

1. 覆盖安装后打开应用，进入日程和闪念，退出再重开：应正常进入，原有记录及状态保留，没有数据库升级错误。本轮大姨妈页面尚未接入。
2. 打开已有日程和闪念详情，查看原图、附件、正文和原有聊天：内容应完整，图片可预览，文件可通过原方式打开。
3. 编辑一条闪念并保存，完成后恢复，再重开：文字与状态应保留，列表和详情同步，原有附件仍可访问。
4. 进入模型与 API、通知提醒及外观设置：原配置和主题应保留，已有铃声仍可试听，既有日程提醒规则保留。

大姨妈新表的直接读写由自动化测试验证；手机上的新页面及录入流程按后续步骤交付。

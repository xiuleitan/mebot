# 主库兼容恢复（0.21.1）

2026-10-25，日程出现日期标记、列表和聊天读取失败，闪念出现数量、列表及输入框恢复失败。这些功能共用 Room 主库，主库无法打开会使多个操作同时失效。

## 定位依据

只读检查手机数据库：SQLite 完整性检查通过，外键无违规，原日程、闪念、草稿及附件关联仍在。数据库版本为 13，结构标识为 `58a93f89d99ef3e8e95e78c96b83e082`；当前代码的 schema 13 标识为 `9d59382fed4b57d85d0b676a2c0da765`。逐表比较字段、索引和外键后，发现手机库仅缺少 `dayima_span_markers.needsReview` 字段。

开发期间先安装了含提交回执表的版本 13，随后又在同一版本新增待复核字段和迁移逻辑。对已经处于版本 13 的手机库，Room 不会再次执行 12→13 迁移，而是在打开时拒绝不匹配的结构标识。多会话共用代码、版本号、生成文件及安装流程，使这种中间状态进入了手机。

修复前的数据库副本及源码快照保存在开发机项目目录以外的私有临时目录，不纳入源码、APK 或业务导出。

## 修复方式

- 主库升级至 14，应用升级至 0.21.1（versionCode 80）。
- 13→14 迁移检查跨度表的实际列结构；缺少 `needsReview` 时补齐，并将已失效的跨度标为待复核，保留原始快照及文字。
- 完整的版本 13 不重复加列，不改变用户已有复核状态或业务记录。版本 12 及更早版本沿用原有迁移链后进入 14。
- 结构迁移与 Room 全表校验处于升级事务内；校验通过后由 Room 更新结构标识。校验失败则回滚，不清库、不手动放行不匹配结构。

## 验证范围

专项回归覆盖两种版本 13、原有复核决定、过时和缺失端点的跨度、提交回执序号连续性，以及故意破坏索引后的迁移回滚。升级前后对比全部业务表的已有字段与行，检查文件字节和外键，再验证日程、日期标记、闪念列表、数量与草稿查询，并关闭重开数据库。

另在开发机上用手机数据库副本验证迁移。手机上的功能和交互由用户验收，覆盖安装不清除应用数据。

交付结果：清理旧产物后的 Debug 构建成功；361 项项目测试及 1 项真实数据库副本迁移测试全部通过，无失败、错误或跳过。真实副本升级并重开后，36 张业务表原有数据的摘要全部一致。Lint 无错误或检查异常。0.21.1（versionCode 80）已通过 `adb install -r` 覆盖安装至 PMW110，返回 `Success`，安装版本已核对；首次打开 App 时执行主库迁移。

## 手机测试

1. 更新后重新打开 App，分别进入日程和闪念：原有卡片、日期圆点和数量应出现，不再显示读取失败或输入框恢复失败；切换日期、完成状态后，内容对应正确。
2. 打开原有日程详情并查看图片／附件，执行完成后恢复；重新进入页面，状态应保存，侧栏和首页按钮可用。
3. 在闪念新建一条测试记录，打开详情、编辑、完成、恢复，最后删除该测试记录：列表、数量和统计应同步；原有记录保留。
4. 输入一段尚未提交的闪念文字，切换页面再重开 App：已保存草稿应恢复。查看模型配置、铃声和主题，原配置应保留。
5. 日程及闪念分别打开加号图片面板：默认最多三行，加载更多增加三行，已选图片保持；切换亮暗主题、展开／收起统计，检查过渡及按钮响应。

后续多会话修改需划清文件范围，由一个会话统一管理主库版本、迁移、集成构建和安装。数据库结构在安装后发生变化时必须增加版本，不能只替换同一版本的实体、历史迁移或结构标识。

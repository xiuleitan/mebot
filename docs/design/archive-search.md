## 首次启用与使用

1. 在 **App 设置 → 模型与 API → 档案语义搜索** 中点击“配置语义搜索”。默认建议 `qwen3.7-text-embedding`、1024 维、DashScope 协议；地址从现有模型设置建议为同一主机下的向量地址，保存前可以独立修改。档案首页不再显示“新建档案、索引、会话记录”一排入口。
2. 核对 HTTPS 地址与凭据来源，默认复用上方已保存的安全 API Key，也可以单独保存向量接口密钥。启用并点击“保存搜索设置”一次后，后台自动为已有已确认档案建立索引；未配置或未启用不会发请求。进入配置、开合弹层本身不创建档案或会话、不改写设置，也不调用模型。
3. 之后新建或修改档案并确认保存，立即显示本地保存结果，后台自动为本条的新版本建立索引，无需每次再点设置按钮。首页只在搜索中、准备搜索或失败时显示相关状态；详细进度和重试/重建留在设置中。首页底部输入用于 AI 建档，生成草稿后才显示核对编辑入口；已有档案详情进入原会话后仍可手动编辑。
4. 顶部输入“我的中国银行卡”“我的身份证”等自然语言，按键盘搜索或点放大镜提交。结果直接在原卡片区域按语义关联度排列，显示命中片段；点卡片看详情，再点“编辑档案”回到它原来的聊天。
5. 清空搜索或点“全部档案”返回本地列表。新查询需要联网；失败保留查询和原档案，可重试，也可主动选择“本地文字查找”。后者明确显示为文字匹配、按最近更新显示，不与语义分数混排。

## 确认、修改与删除

模型只产生候选。人工核对表单显示本次修改的区域（标题、正文、具体信息、附件等），冲突需逐项确认；只有本地确认事务成功才显示保存成功。同一操作重试返回同一回执；从原会话继续保存只修改既有 ID。

完全相同的确认不提升业务 revision，也不重建已有效的向量。真正变更时，在同一事务写入正式内容、附件关联及操作回执，并立即撤销原向量及旧索引令牌、排入新版本任务。版本冲突保留未确认内容，必须明确重新载入后再核对。

详情删除需确认范围，正式卡片及索引立即移除，固定绑定墓碑使旧 AI/索引响应无法复活它。原聊天、历史附件引用和未关联其他卡片的历史按既有规则保留；重建派生索引不删正式档案或原件。

## 在线向量与后台任务

- Native DashScope：`input.texts` 输入，`parameters.dimension` 指定维数，入库/查询分别用 `text_type=document/query`，请求 dense 向量。兼容 API：`input`、`dimensions`、`encoding_format=float`，采用协议默认的对称纯文本编码，不发送原生专用参数。接口依据：[百炼文本向量同步 API](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)。
- 只处理用户确认的标题、类型、标签、字段、正文和短链接语义。排除原始聊天、未确认草稿、附件 ID/原件、标识出的密码/密钥段、冗长号码与 URL 查询参数；不猜测银行、类型或号码，不抓网页/PDF/音频正文。
- 普通档案一条向量。长内容按 UTF-8 字节预算分段，每段含对象标题上下文且不截断 Unicode 字符；单次请求最多 7000 UTF-8 字节，投影最多 600000 字节、100 段，超限明确失败而不发布残缺索引。这是本地请求预算，不是把字符数当模型 token 数。
- 指纹包含 endpoint、模型、维数、协议、query/document 编码、归一化格式及投影/分段版本，排除 key。换 key 不全量重建；换空间或禁用使旧索引/令牌失效。重建另提升配置 revision，使相同空间下的旧查询页也失效。
- WorkManager 使用已有网络约束、持久工作链与退避。保存的索引任务先在 Room 中提交；调度失败不回滚档案，下次启动、页面恢复或手动操作重新登记。每批最多领取 8 份，仍有可执行任务时由 WorkManager 继续退避执行，不承诺后台精确时刻。
- Application、Worker、页面共用同一协调器，首次领取前只进行一次有序中断恢复；每次 Worker 或页面进入都不会撤销有效令牌。写回同时检查 record revision、配置指纹与随机 lease token；每段请求前也检查任务仍有效。
- 网络/超时/限流/服务暂态失败最多自动尝试 3 次；鉴权、配置、格式等非暂态失败等待修正和手动重试。请求层不重定向、不自行重试；读等待 35 秒、总等待 45 秒，Worker 每次受 8 分钟执行预算约束。

## 检索、缓存与数据一致性

文档与查询向量验证维数、有限数值和非零范数，归一化为 Float32。文档向量及检索文本均加密保存在共用 Room 主库；没有引入端侧模型、额外业务数据库或业务后端。

搜索在 IO/计算后台每页读取 128 条有效向量做点积，即余弦关联度；按档案取最佳分段分数，再降序、以稳定 ID 打破同分。没有关键词置顶、字符串强行加分或任意固定阈值。只保留 ID/revision/分段/分数用于稳定分页，展示时按需重新加载正式内容、命中片段与缩略图。

分页不会重新生成查询向量。同一空间/同一句查询的向量有最多 4 条、5 分钟有效期的内存缓存，不作为查询历史落盘。档案或任务变化时可用缓存重新排序；缓存失效时提示用户明确重新搜索，不后台重复付费。新输入、取消、新搜索后迟到响应不能覆盖当前查询。

结果展示前重新核对当前正式版本、READY 任务和有效配置；修改/删除后旧页不再提供旧内容，配置切换/禁用/重建后旧页拒绝展示。UI 明确区分加载、没有档案、索引未就绪、服务失败和本地文字匹配，并显示尚未纳入索引的档案数量。

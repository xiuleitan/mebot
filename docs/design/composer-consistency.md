# 各 Bot 底部输入约定

2026-10-28，按用户要求以日程为基准检查五个 Bot 的底部输入栏，统一可共用的样式与输入交互。

## 共用实现

- `BotComposerInput`：30 dp 输入外框、主题底色与分隔线，14 sp／21 sp 输入文字，最多显示三行；加号和发送均为 48 dp 圆形按钮、1 dp 主题描边。发送禁用时图标跟随禁用颜色，键盘使用发送动作，与右侧按钮走同一个提交回调。正在提交或不满足条件时，两种入口都不能重复提交。
- `ComposerPendingMediaRow`：96 dp 高的待发送附件条，图片宽 88 dp、普通文件宽 132 dp；移除按钮保留 48 dp 独立触控区，并统一浅圆标位置。右侧提供继续添加入口，导入／发送等忙碌状态禁用移除和添加。缩略图与原件由各 Bot 自己读取，记录详情中的图片排版保持原样。
- `BotComposerWorkspace`：日程、订阅、大姨妈和档案共用输入区、媒体面板与任务浮窗。任务浮窗背景采用[统一的 56% 黑色遮罩](bottom-sheets.md)。浮窗顶部统一紧凑布局、透明底清空／关闭按钮；收起时保存待写输入、关闭附件面板、清除焦点并隐藏键盘。加号面板开合、转角、内容增高和浮窗过渡沿用日程时长。

## 检查与调整

| Bot | 本次调整 | 保留的业务处理 |
| --- | --- | --- |
| 日程 | 输入栏与附件条提取为共用组件，保留原外观及条件；发送禁用图标正确变淡 | 消息、模型处理、日程保存、周期、附件和草稿目标保持原实现 |
| 闪念 | 移除独立输入栏及不同按钮样式；键盘改为发送；共用附件条和继续添加入口 | 仍直接保存本地闪念，成功后清空已提交草稿，失败保留输入；不新增会话或联网条件 |
| 订阅 | 统一边框、浮窗顶部、收起处理、附件条及按钮禁用条件；进入后台提交待保存输入 | 仍使用原订阅会话和提议确认流程，图片与消费数据规则保持 |
| 大姨妈 | 统一紧凑浮窗、收起行为、附件条及继续添加；收起有消息／处理中任务后可重新打开 | 正式记录、备注、图片与任务隔离仍由原 ViewModel 和 Repository 管理；空白任务无展开入口 |
| 档案 | 统一边框、顶部操作、收起处理及附件条，普通文件使用较宽预览，处理中不直接提交下一条 | 首页新建入口与卡片原会话保持隔离，草稿与附件继续存入本地，原分析版本校验保持 |

不同 Bot 的提示文案、允许的附件类型和正式业务提交不强行替换。附件类型校验、保存、失败重试与恢复仍由其本地代码负责。本轮不修改 Room 结构、历史迁移和持久文件格式。

## 手机验收

1. 依次打开五个 Bot，比较输入栏圆角、按钮大小／描边、明暗主题下底色及禁用图标。输入长文字，均最多显示三行并可滚动；较大系统字体下按钮仍完整可点。
2. 输入可提交内容，分别使用右侧按钮与键盘发送；两者执行同一业务提交。空白时不能发送，正在提交时连点不得增加重复记录；闪念仍能断网直接保存。
3. 点击加号、选一张图片，再点继续添加、移除图片；检查缩略图、独立移除触控区和顺序标记。取消相册或拍照保留原文字与附件；导入过程中不能再次移除／提交。
4. 附件面板与键盘切换、系统返回、收起任务浮窗，检查面板优先关闭、键盘隐藏和过渡连贯；长列表底部内容不被输入栏遮挡。
5. 各 Bot 留下一段未发送文字与附件，切换页面、进入后台并重开，确认草稿仍属于原目标；保存后首页新建和详情继续聊天的目标保持各自原规则。收起大姨妈处理中任务后可点入口重新查看。

# 大姨妈本地记录业务

开发步骤二，版本 0.21.0。新增 `DayimaRepository`，通过 `AppContainer.dayima` 提供本地业务入口。主库通过保留数据的 12→13 迁移新增提交回执，并为跨度标记增加持久的待复核状态。

本轮完成数据层操作，界面仍在第四步接入。记录与资料的保存不调用模型、网络或后台服务。

## 操作范围

| 请求 | 行为 |
| --- | --- |
| `recordTodayRequest` 与 `RecordPeriod` | 按手机当前时区确定今天，或补记明确的过去日期；同日已有记录时复用该记录 |
| `EditPeriod` | 按 ID 和预期版本更正开始日期，保留 ID 与创建时间；目标日期已有另一条记录时报告冲突 |
| `DeletePeriod` | 按 ID 和版本删除，保留文字备注并解除其关联；相关跨度保留快照并进入待复核 |
| `SaveBirthDate` | 首次填写、修改或清空出生日期；首次预期版本为 0，之后使用读取到的版本 |
| `AddNote`、`EditNote`、`DeleteNote` | 保存独立或关联经期的文字备注，支持更正发生日期、内容及关联；完整保留原文和换行 |
| `SaveSpan`、`DeleteSpan` | 标记相邻两次记录之间的漏记／特殊阶段，修改说明、显式复核或移除标记 |

实际经期、备注发生日期与出生日期不能在未来。备注正文必须非空，关联经期必须存在；经期和备注的创建时间记录首次保存时刻，后续编辑不改写。更正经期开始日期不会自动更改备注自身的发生日期，需要时单独更正备注。

记录经期时可同时提供备注，两者和提交回执在一个事务中保存。同一天通过另一份新请求再次记录不会新增经期；新请求明确提供的备注作为一条独立补充保存。同一次请求的重试不会重复添加备注。

`recordTodayRequest` 在创建请求时固定日期，之后即使跨午夜也不重新解释“今天”。例如先建立本次请求，再执行：

```kotlin
val request = container.dayima.recordTodayRequest("本次补充情况")
val result = container.dayima.execute(request)
```

失败重试复用该对象或同一 requestId 和参数；用户修改内容后建立新的请求。出生日期、记录、备注和跨度写入统一返回实际保存的实体或删除结果，数据库事务成功后才返回成功。

## 重复提交与失败恢复

每个请求在提交前有一个稳定的 `requestId`。`dayima_write_receipts` 使用唯一 requestId 保存请求指纹、操作类型、目标及结果版本。指纹使用固定字段顺序和长度前缀，区分空值、换行及分隔符，不保存正文副本，不输出个人资料日志。

- 同一请求并发或重开后重试，只产生一份提交回执；不重新写入、不刷新记录时间，也不重复增加备注。
- 同一 requestId 携带不同内容或改成另一种操作时报告请求冲突。
- 目标后来被编辑或删除，旧保存请求报告冲突，不覆盖新版本，也不把记录重新创建。
- 删除请求只针对原 ID，重复执行不会误删后来在相同日期创建的新记录。
- 备注和跨度在解除经期关联时增加版本，使旧的子记录编辑请求失效。

回执与全部业务修改处于同一 Room 事务。记录、备注、关联处理或回执写入任一步失败，整笔事务回滚，原状态和调用方持有的不可变请求保留。跨表逻辑及请求指纹计算避开界面线程；异常向调用方报告，供后续页面保留输入并提供重试。

回执独立于聊天和业务记录存在，不会因清空聊天或删除一条记录而丢失。它用于提交去重，不是模型记忆，也不会创建额外聊天。

## 跨度复核与一致数据版本

补记或移动记录进入已有标记的跨度，或修改它的端点日期后，标记进入持久的 `needsReview` 状态，快照日期和说明保留。即使随后删除中间补记、原端点再次相邻，旧标记仍待复核。用户明确复核时检查当前端点版本、日期顺序和相邻关系，再保存新快照并清除该状态。

删除端点时解除引用并保留标记；删除标记后，旧的保存请求不能重新创建它。`spanMarkers()` 同时检查持久状态与当前邻接、日期和版本，供后续界面及统计识别待复核项。

每份新成功提交的回执有一个递增序号，作为本地 `dataVersion`。新请求即使没有改变字段也保留回执；已提交请求的重试和失败事务不增加版本。序号不依赖系统时钟，便于后续统计识别数据变化。

`recordsSnapshot()` 在同一事务内读取版本、出生日期、全部开始日期及跨度标记，提供一致的事实快照；`observeDataVersion()`、`observePeriods()`、`observeProfile()` 提供订阅入口。本轮尚未实现周期计算和图表。

## 数据升级与开发验证

12→13 迁移保留现有日程、闪念和大姨妈记录及聊天，新增 `dayima_write_receipts` 与 `dayima_span_markers.needsReview`。原标记若已经缺少端点、日期／版本不匹配或端点不相邻，在升级时标为待复核并增加标记版本；其原始快照和说明保留。

本轮 35 项大姨妈专项测试通过，包括 23 项 Repository 测试及 12 项存储／升级测试。重点覆盖：

- 手机时区、跨午夜请求、重开恢复、同日复用及并发重试。
- 更正冲突、未来日期、空备注、无效关联、出生日期修改与清空。
- 旧请求不能覆盖新版本、删除后不恢复、同日新记录不会被旧删除误删。
- SQLite 触发器模拟备注与回执写入失败，验证新建、删除、关联处理和跨度失效的整笔回滚。
- 跨度的邻接校验、持久待复核与显式重新绑定，时钟回拨不改变版本递增。
- 从实际 schema 12 建库，填充旧业务数据和独立聊天后升级，验证旧列、索引、外键及待复核迁移。

交付结果：全项目 358 项测试通过，lint 无错误，Debug APK 构建成功；0.21.0（versionCode 79）已覆盖安装到已连接的 PMW110 手机，安装结果为 `Installed on 1 device`，手机包版本已确认。

## 本轮手机验收

1. 覆盖安装后打开日程和闪念，退出再重开：原记录和状态保留，应用正常进入，没有数据库升级错误。本轮尚无大姨妈页面。
2. 打开已有日程与闪念的正文、图片、附件和聊天：内容完整，图片可预览，文件可按原方式打开。
3. 编辑一条闪念，保存后完成、恢复，再重开：文字和状态正确保存，既有附件仍可使用。
4. 查看模型配置、铃声和主题：原配置保留，既有铃声可试听，导航及弹层交互正常。

大姨妈业务操作由开发机真实 SQLite 自动化验证，第四步接入页面后再交付相应手机录入测试。

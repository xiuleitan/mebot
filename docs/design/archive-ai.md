## 用户流程

1. 首页底部用于登记新档案；输入文字或添加同一份档案的图片后发送，打开该档案自己的聊天。消息及附件先在本机持久化，随后显示“正在整理图文资料”，可取消；等待期间可关闭聊天并登记另一份档案。
2. 默认使用共用设置中的 `qwen3.8-flash`。返回完整草稿后，聊天中显示标题、主要字段、正文与待确认数量，点击“核对整理草稿”进入可编辑表单。
3. 图片模糊、文字与图片矛盾等情况逐项显示待确认信息。修改字段不会自动清掉这些项目；用户修正或核实后逐项点击“已核对这一项”，全部解决后才能正式保存。
4. 上下文不足时简短追问；聊天内继续发送补充资料会结合本会话已有内容生成完整草稿。同一证件正反面合并为一份档案。关闭聊天或确认保存后，首页回到新建输入；已保存卡片的“详情 → 编辑档案”直接重开首次建档的聊天记录，继续修改同一档案。手动表单保留在聊天内的核对入口。
5. 一次会话只处理一个对象。请求新增另一个对象时提示新建会话；已有草稿或正式对象的标题、类型不能被模型静默替换，明确的改名/分类要求才允许修改。正式写入始终使用本地固定的会话目标。
6. 失败、取消和中断保留原消息、附件及既有候选，可手动重试或手动建档。重试不会再添加一条用户消息，不自动重复付费请求；重启只恢复状态，不自动发模型请求。

## 实际请求内容

语言模型和 endpoint 从现有 `ModelSettingsRepository` 读取，凭据经现有安全接口取出；不覆盖用户设置。没有配置、凭据不可读或接口不支持图像时如实显示错误，已有本地管理继续可用。

请求使用 OpenAI 兼容 Chat Completions：用户 `content` 同时包含 `type: text` 与每张图像的 `type: image_url`，`url` 为真实 JPEG 的 Base64 Data URI。不会把文件名、路径或附件 ID 当图片，也不通过公共 FileProvider 导出模型输入。只提供当前会话必要历史和当前候选/已绑定档案，剔除内部 ID、附件路径与重复原始输入，不读取其他会话或全库档案。

非图片文件只登记名称与类型，明确告诉模型未读取正文；本步没有 PDF 提取、音频转写、视频理解或网页抓取。链接仅从用户显式 HTTP(S) 文字解析，模型只按编号生成名称；本地保留原始地址、顺序和重复次数，模型不能替换 URL。

接口依据：[阿里云图像理解文档](https://help.aliyun.com/zh/model-studio/vision)中的混合文字/图片消息与 Base64 图像输入，以及[结构化输出文档](https://help.aliyun.com/en/model-studio/qwen-structured-output)的 JSON Object 模式。请求关闭 thinking，限定完整 JSON，并由本地重新校验决策、字段类型、大小、链接名称数量与附件归属；截断或不符合约定的响应不能落为草稿。模型不能指定档案 ID、执行保存/删除或报告执行成功。

## 图像、长度与取消边界

- 图片仅从经过认证的本地加密原件临时解密，处理后立即删除私有明文文件。所有支持的 Android 版本使用相同的有界 BitmapFactory 解码与 EXIF 旋转/镜像处理，透明区域填白；原件不改写。
- 单张原图最多 20 MiB，最长边最多 2560 像素，JPEG 单图最多 2 MiB；单次最多 6 张，Data URI 合计最多 11 MiB。当前消息的图片超限时直接提示，不悄悄丢弃；历史图片按最近资料补足，未重复发送的数量在回复中说明。两个并发整理上限控制图片内存和网络等待。
- 本次文字最多 16,000 字符，当前档案主要文本最多 20,000 字符，必要对话约 30,000 字符，总文本和链接有额外上限。超限提示缩短或手动编辑；较早历史截取时说明。
- 复用现有可取消 HTTPS 传输，单次读取 45 秒、整体 60 秒；不自动重试。取消、继续输入、手动编辑、新请求和正式目标更新都会使旧请求失效。
- 本地落草稿时同时核对会话、请求令牌、草稿 revision、请求时的正式档案 revision；结果只写原会话。目标已删除、被其他会话更新或输入已变化时拒绝旧结果，不覆盖新输入、不复活档案。
- 请求状态、冲突与来源链接加入既有加密草稿 JSON 的可选元数据；旧草稿缺少此项时仍能读取，旧版本读取也保留既有数据字段。Room 实体与 schema 17 完全不变。

## 自动检查与手机验收

自动检查使用合成资料、真实 Room/加密文件、受控传输与原生位图解码，不调用真实付费 API，也不读取个人 API Key。覆盖文字和正反面请求、前导零、原始链接保真、严格响应校验、冲突阻止确认、多会话及取消迟到结果、重试不重复消息、重启中断恢复、失败后手动保存、图像大小/方向/透明度及原件不变。检查数量和实际安装来源以交付记录为准。

手机测试由用户完成：

1. 检查共用模型设置为可用的 `qwen3.8-flash` 和 API Key，新建会话仅发送一段地址/网络资料。预期出现待核对草稿，未确认前列表没有新卡片，核对保存后出现一张。
2. 新建会话，发送一张银行卡图片及说明；再用另一会话发送同一身份证的正反面两张图。核对图像顺序、方向、号码前导零及两面字段，预期每个会话只形成一份候选。
3. 用模糊图片，或文字中写入与图像不同的地址。预期待确认项目可逐项处理，普通编辑不会自动消除冲突；全部核实后才可保存。
4. 保存银行卡后关闭详情，直接从首页输入身份证资料，预期是没有银行卡上下文的新会话。分别点击两张卡片的“详情 → 编辑档案”，各自恢复原聊天；在身份证会话补充说明，只更新身份证卡片。未确认会话关闭后也能从会话记录恢复。
5. 请求等待中切换到另一会话并留下未发送输入，再返回；取消后立即重试，或等待时打开手动编辑。预期迟到结果不覆盖当前输入、手动字段或新请求，重试不重复用户消息。
6. 断网发送测试资料或取消正在进行的整理，确认失败信息、原消息/图片及手动保存可用；重启 App 后恢复本地状态，中断请求只有点击“重新整理”才再次联网。
7. 回归等高双列卡片、图片/文件打开、手动保存与编辑、重复保存、详情删除、历史切换及原有日程功能。后续已实现的顶部语义搜索按[检索验收](archive-search.md)验证。

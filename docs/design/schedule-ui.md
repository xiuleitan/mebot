## 自然语言创建（0.7.0）

- 用户发送文字后，先事务保存原文并清空输入，再使用本机配置的语言模型提取。默认 `qwen3.8-flash`，调用已保存的 HTTPS Chat Completions 地址；API Key 在 IO 线程从 Keystore 加密存储中读取，不进入界面状态、日志、模型输入或导出。
- 使用百炼 [JSON 结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output) 的 `json_object` 模式，关闭思考和流式输出。模型只能返回 `save / edit / delete / stop / ask / reject` 之一，不能调用工具或直接执行数据库操作。本地检查字段集合、类型、日期、严格 `HH:mm`、周期、提前分钟数和 1～30 个 Unicode 字符的新标题；历史标题原样保留。拒绝秒、类型强制转换、额外执行字段、截断响应及外会话问题 ID。
- 输入只包含当前任务会话的文字、发言时间、设备当前时间／时区、当前任务快照、待补充问题及当前会话的附件总数／图片数／文件数，不发送图片、文件内容或其他会话。按完整消息保留首条需求和最近最多 60 条上下文，文字上限 24000 字符并告知模型历史是否裁剪；本地原始历史不删除。相对日期以对应发言时间为参考，未提供日期默认设备当天，具体时刻已过且仍需提醒时追问，不擅自安排到明天。
- 一次采购是一个任务，“土豆、猕猴桃”放入详情并生成简短标题。继续“再加茄子、辣椒”更新同一任务，完整保留其他字段和封面。明确要求两个不同时间的独立活动时，引导分别新建，不拆采购物品，也不在同一会话新建多条逻辑任务。
- 仅日期任务不生成 00:00 或闹钟。有具体时间时默认 `[10, 0]`，分别表示提前 10 分钟与准点提醒。用户指定的提前量替换默认提前量，支持多次提前量及明确关闭提醒。日期和时段明确但无提醒时刻的活动可保存仅日期，有提醒意图且缺少明确时间时追问。明确秒级请求在本地联网前就提示改成分钟级，模型识别的其他秒级请求也不保存。
- 支持每天、每周指定星期、每月指定日期、间隔若干天、结束日期。按当前结构化规则执行，不逐日调用模型。周期规则没有实际发生日期或新建时处于暂停状态，会先追问，避免保存一项没有卡片的新任务。新建每周任务时切到首次实际发生的日期，而非未发生的起始日期。
- 网络请求在事务外完成；收到结果后再次校验会话、最新用户消息、任务版本和时区，避免旧结果覆盖新内容。任务、操作请求、助手成功回复和明确已答复问题在同一 Room 事务中提交；任何写入失败全部回滚，不出现任务保存了却没有执行回复的半完成状态。未持久化前不显示“已创建”。
- 创建成功后关闭聊天浮窗、键盘及媒体面板，主列表切到实际发生日期、更新圆点并滚动到新卡片；会话中的任务卡片和原消息仍保存，之后从详情“编辑”继续。普通任务补充或改期复用同一任务及发生 ID，编辑成功不自动关闭聊天。周期编辑先明确本次或后续（可指定起点），删除采用本次或整个周期；普通任务明确删除即执行。
- 关闭浮层不取消已开始的解析，可先写下一段草稿；新输入不会被前一轮回复清空。清空未完成草稿会取消请求，事务还会检查旧会话是否仍存在，即使迟到也不能生成被丢弃任务。切换到其他会话会取消当前等待，原会话的未处理消息可稍后手动重试。
- 模型格式、结构字段或本地内容校验不通过时自动重新请求，同一条消息最多尝试 10 次（含首次），重试间隔 250 毫秒，并显示当前次数。有效追问正常展示；断网、鉴权／额度、配置、超时及本地保存错误不进入格式重试。每次请求仍采用 30 秒读取超时、40 秒等待上限。任务、操作和成功回复只在校验通过后原子提交；重试仍校验原消息、任务和发生版本，防止旧请求覆盖后来的修改。已经提交的消息不再次调用模型或重复建卡；进程中断后的待处理消息保留，重新进入不自动启动另一轮调用。

## 聊天字号、自动重试与创建后定位

日程的用户和 AI 气泡正文及追问缩为上一版字号与行高的 3/4：主消息 14 sp、21 sp 行高，仍跟随系统字体缩放。消息气泡上下内边距缩至 8 dp，图片与文字之间间距为 6 dp。状态提示和卡片、输入框保持各自字号。顶部操作为透明底色，无额外上下留白，触控范围为 48 dp；仅确认尚未创建日程的草稿显示垃圾桶，已创建任务的会话只显示叉号，读取期间不先闪出垃圾桶。共用输入组件通过日程专用选项启用此样式及外部关闭时的输入收起行为。

底部不再展示“这条消息尚未完成解析，可点击重试，或继续补充描述。”。已有日程的历史中断提示及其重试行整体隐藏；尚未创建任务的中断草稿仅保留继续处理的按钮，避免没有操作入口。实际网络、模型校验失败、保存错误与冲突仍按原流程提示，自动校验重试的次数及上限保持原规则。

新建完成事件携带事务实际生成的发生 ID 与日期，周期任务使用首次真正发生的那张卡片。界面先收起聊天并选定日期，待对应数据就绪、日期翻页停稳后滚动到卡片；不等待 AI 封面生成。定位目标独立于聊天草稿，关闭后切换新草稿或旋转重建不会丢失；定位后清除，用户离开目标日期也会取消尚未完成的定位。已完成分区标题占据一个网格索引，定位计算包含此偏移。

手机验收：在有长列表的当天创建任务、再创建其他日期的任务，应自动回到主界面并看见新卡片；周期任务应定位首次实际发生日。给出缺少具体提醒时间的需求时，聊天应留下追问；从已有任务详情进入编辑，修改后仍留在会话。检查两侧气泡比上一版缩小约 1/4，已有任务右上角只有叉号，底部没有旧的未解析提示；未创建草稿仍可清空。若模型校验失败，应显示自动尝试计数，成功后只出现一张卡片，达到 10 次后保留原消息并显示失败。重试中清空或切换任务后，旧请求不能继续创建或覆盖。亮暗主题、大字体、键盘弹出及媒体面板展开时重复检查关闭、定位和继续编辑。
- 0.7.0 不生图、不上传附件、不登记系统闹钟；无图卡片沿用日历占位。提醒配置真实保存在本机，助手和界面均说明暂不响铃。0.7.0 使用 schema 3；0.8.0 的单次例外、消息目标与文件清理使用 schema 4，通过迁移保留既有数据，不清库。

## 补充、编辑与直接删除（0.8.0）

- 不提供聊天查询。相关输入引导打开详情，不返回任务信息的问答结果；列表、圆点、详情所需的本地数据库查询继续正常使用。
- 模型对已有任务返回 `edit`，仅列出本轮需要修改的字段，本地通过 `SchedulePatch` 合并。时间修改不改标题、详情、日期、周期或提前量；采购补充写回完整详情，始终复用原任务。明确取消具体时刻时才将时间置空并取消提醒；仅修改详情时允许保留历史时间，不误要求重排日程。
- 从某张详情进入会话时，将卡片 ID 保存到本次用户消息的上下文中，重试和重启后仍可找到原目标。周期修改范围包括本次和后续，范围不明确先追问；0.9.0 支持指定后续修改起点。模型的 `target_date` 在本次修改中表示原发生日期，在后续修改中表示范围起点，改期后的日期写在补丁字段中，避免把“明天那次改到后天”误认成修改后天那次。
- 单次编辑修改卡片快照及其独立提醒，不修改周期模板，完成／恢复后仍保留单次提醒配置。未来模板修改保留已完成及过去快照；对于已有单次例外，仅合并本轮修改字段，例如统一改时间仍保留那次的特殊备注和提前量。周期起始日期已过去时，调整未来时间按下一次有效发生日期处理，不强迫改写原周期锚点。
- 普通任务的明确删除指令直接执行，不再询问确认。整个任务删除在同一事务中移除任务、发生卡片、提醒、模板版本、会话消息、输入草稿、追问、附件关联和操作历史，不保存删除快照或回收站。失败完整回滚，原内容可重试；迟到的模型结果和陈旧的界面保存不能重新创建被删除任务。
- 周期删除范围为仅本次或整个周期。仅删除本次时物理移除该卡片、提醒及关联操作记录，只在仍生效的周期规则中登记排除键，避免重新浏览时再次生成；其他日期共用的任务和会话继续保留。整个周期删除移除全部日期及共用会话，不保留历史。没有明确范围时先问清，明确范围后即删除。
- 详情中的删除按钮先弹出确认框，左侧“取消”、右侧“确认”，其余界面被半透明遮罩覆盖并阻止点击；只有确认才调用删除。周期任务先选择“仅删除本次／删除整个周期”，再确认对应范围。取消、系统返回或点击遮罩只关闭确认框，详情与任务保留。这个入口只调用本地事务，断网和无模型服务时也可使用。成功关闭详情并更新列表、圆点，失败保留原详情并提示重试；会话中的明确文字删除指令保持直接执行。
- 删除后清理不再被其他记录引用的媒体元数据和应用持久图片副本，共用文件及用户相册原件不受影响。事务先登记待清理路径，之后在 IO 线程删除文件，清理失败下次启动继续；清理与导入串行，重新导入或重新注册的文件不会被旧清理任务删除。内存封面缓存也会清空。
- schema 3 → 4 只新增消息目标列、单次例外标记、独立提醒、周期排除表和媒体清理表。原有任务、最近草稿、会话、提醒和 Keystore 加密凭据保留；兼容 schema 1 → 2 → 3 → 4 的连续升级。

## 页面与数据库（0.6.0）

- `ScheduleViewModel` 按选中日期订阅 Room 查询；一次联表取得日程快照、所属会话及封面引用，不逐卡查询。切换日期先清空旧日数据并展示读取状态，取消旧订阅，避免快速连续切换时串日。
- 日期圆点来自真实日程计数，包括已完成任务，排除已删除任务和被规则隐藏的发生记录。只订阅日期栏可见范围前后各七天；临近范围边缘再移动查询窗口，不一次加载全部历史。日期索引使用固定基准，系统重建和跨日后不会改变原索引对应的实际日期。
- 周期规则按当天及日期栏附近的范围展开，保留历史模板版本与每次发生的独立完成状态。模板版本流只读取任务 ID 与版本号，新建、编辑、删除后重展当前范围；完成卡片不反复触发展开，也不重复生成卡片或提醒记录。
- 详情单独按发生 ID 订阅，与列表共用数据库记录。任务被修改、移动日期或删除后会更新详情；不可见记录显示已删除／不再显示，查询失败提供重试。不同日期的同一周期任务通过同一个 sessionId 打开原会话。
- 完成／恢复由本地事务校验会话、发生 ID 和版本，提交成功后才更新界面与排序；旧查询结果不能覆盖刚提交的新版本。写入中禁用重复点击，失败保留原状态并提示重试。完成日期仍保留圆点，恢复时继续使用现有提醒状态规则，本轮不注册系统通知。
- 页面离开或应用进入后台停止查询订阅；已开始的完成写入继续在 ViewModel 中提交。系统重建恢复选中日期；从侧栏重新进入选中今天。冷启动重新读取本地记录，不依赖内存中的完成列表。
- 数据库通过保留数据的迁移升级至 schema 4，没有清库、种子数据或破坏性迁移。既有会话、最近新建草稿、模型配置和媒体原文件均保留。无真实任务时显示空列表，0.7.0 可通过自然语言创建真实记录。

## 周期日程与范围（0.9.0）

- 每天、每周指定星期、每月指定日期、间隔天数和结束日期均由本地结构化规则展开。卡片增加循环图标，详情展示周期规则与“每次独立完成，共用会话和封面”。完成／恢复只改变当前发生记录。
- 从某张卡片进入会话，顶部显示本次日期，底部任务卡片也保持为选中的那次；其他日期仍打开同一消息历史。卡片单次改期、Activity 重建、切后台后不会悄悄换成最近一次。
- “只改本次”修改所选发生记录的标题、详情、日期、时间或提前量，不改模板。单次提醒在完成／恢复后仍保持独立配置；单次改期不会按原日期重新生成一张卡片。
- “修改后续”默认以所选卡片改期前的原发生日为起点，含该次；明确“从今天起”“从明天起”或指定日期时，以用户指定的起点执行，且不改写过去和已完成记录。回复明确写出起始月日。仅修改时间不重设间隔规则的起始日期，也不丢失单次备注及独立提醒。
- 模板版本保存实际生效日期。范围之前尚未展开的日期仍使用旧版本；后续修改覆盖从该起点起的未完成日程。范围起点采用当天有效的模板，不意外继承另一条未来预定修改。被删或已完成的首个发生日不阻止找到下一次可用卡片。
- 新增 `stop` 解释动作和本地 `stopRecurrence` 事务。会话明确“停止整个周期”，或在详情直接点击同名按钮，均停止今天及之后未完成的卡片与提醒；过去、已完成记录、封面、共用会话保留。停止后浏览更远日期或重启应用，不重新生成未来卡片；恢复完成状态也不能重新启用该周期的提醒。详情历史卡片显示“已停止重复”。
- 停止与删除分别处理：删除整个周期仍物理清理全部任务、卡片、提醒、会话及历史；仅删除本次只移除该次。否定、询问停止或仅关闭提醒的文本不能通过 `stop` 执行。
- 各次发生只引用已有封面资源和同一会话，展开周期不调用模型、不导入复制封面、不逐日生图。0.10.0 已接入用户附件选择，0.11.0 新建任务无用户图片时自动生成一张共用封面。
- 本次继续使用 schema 4，不需要清库或表结构升级。周期设置、生效版本、单次例外、完成状态及停止规则均持久化在本地主库。

## 本地图片、文件与封面（0.10.0）

- 新建／任务会话和日程详情提供“图片”“文件”入口，分别使用系统照片选择器与文档选择器。可多选，不申请整个相册或存储的读取权限。取消选择不产生附件或聊天消息。选择器结果绑定发起时的会话 ID，Activity 重建可恢复该关联；旧会话被清空或删除后，迟到结果不能落到新任务。
- 选中后在 IO 线程复制到 `filesDir/media/originals/`，不依赖临时 URI 或原文件继续存在。流式限制图片 50 MiB、普通文件 100 MiB，校验图片的实际格式及尺寸；按 SHA-256 去重，同一内容不重复占空间，同一会话重复选择不重复增加附件数。各会话保存自己的显示名称和选择顺序。
- 附件直接关联会话，不伪造用户／助手消息、不自动调用模型。只有附件而没有文字时不创建任务；选择完成的附件仍随唯一新建草稿恢复。部分导入失败时只保留成功项并提示重新选择，不报告全部成功。文件完成、元数据和会话关联提交失败时不留下半条附件，未登记副本进入可跨重启清理的队列。
- 图片优先用作封面。按选择器返回顺序使用第一张可解码图片；用户明确切换后继续选择更多图片，不覆盖已经选择的封面。图片、PDF、文档等共同计入附件数量。仅有文件时不把文件当封面；生成中或失败时沿用日历占位，0.11.0 可在新建后后台生成装饰封面。
- 卡片日期旁显示回形针和附件数量；会话底部及详情提供可收起的缩略附件栏。图片可在弹窗中按完整比例查看，普通文件展示名称与大小，并可用手机其他应用打开。键盘、小窗口和大字体下使用紧凑入口，点击附件数量查看列表，避免挤掉输入框。JPEG 按 EXIF 方向预览，缩略图和预览在后台按需解码到 256／1024／2048 像素，有界缓存不改变原图。
- “设为封面”在一个事务中更新该任务所有模板和发生记录的图片引用，包括历史和已完成卡片；标题、日期、时间、完成状态、提醒和周期规则保持原值。周期各次共享同一组附件及一份封面文件。模型在处理文字时更换封面，其迟到结果也不能覆盖用户的最新选择。
- 预览内提供“移除附件”。移除当前封面时自动使用下一张图片；没有其他图片则回到占位。只移除当前会话的引用，文件仍被其他任务使用时继续保留。整项任务删除及清空草稿同时清理相关附件，失败回滚；仅删除周期某次不移除共用附件。用户相册或文件管理器中的原件不受影响。
- 普通文件通过非导出的 FileProvider 和单文件临时只读授权交给用户选择的应用，公开目录仅限 `media/originals/`。缺少可打开文件的应用、文件丢失或不可读时显示明确状态，保留日程和其他附件，不使页面崩溃。
- 语言模型请求包含当前会话文字、日程文本字段和附件数量／类型摘要，不包含附件内容、文件名、路径、URI、图片编码或外会话资料。附件的选择、封面切换、查看和移除均无需联网，也不产生模型调用。
- schema 5 增加 `schedule_local_attachments`，保留旧消息附件并迁移到当前会话附件视图；已有任务、周期、完成记录、草稿及加密凭据均保留。正文和提醒仍以结构化业务表为准，附件状态不替代日程状态。

## 附件指代理解（0.10.1）

- 每次发送或重试都在准备模型上下文的本地事务中统计当前会话附件，字段仅有 `total_count`、`image_count`、`file_count`。普通装饰封面和其他任务的附件不计入，添加、移除及应用重启后均以数据库现状为准，不读取媒体内容。
- 动作与日期清楚时，对象可以保留泛称。选择一张图片和一个文件后说“明天把这两个东西收了”，直接创建标题如“收取两个东西”的明天仅日期任务，详情注明参照本任务附件。不能因为不知道具体物品而要求用户重新上传、命名或描述附件。
- 附件数量只代表文件载体，不代表实物数量；用户说“两个东西”就保留该数量，不能按附件数自行改写。模型不得声称已读图或文件，不推测其中的物品、人物、地点或时间。后续“改成后天”只修改日期，保留描述和封面。
- 仍可追问缺失的动作或必要的提醒时间。例如“明天这两个”需明确要做什么；“明天提醒我取这两个东西”只需补充提醒时刻。旧会话里因不知附件内容而产生的追问，在现有文字和附件摘要已足够创建时应视为不再需要，直接保存。

## AI 自动封面（0.11.0）

- 新建成功时，如果当前任务没有封面且没有用户图片，在日程、助手回复的同一事务中登记封面队列；事务提交后才调度。卡片先展示，生图和下载不阻塞保存、改期、完成或浏览。普通文件不影响生成；已有用户图片不调用生图。升级不会批量给旧任务发起付费生成。
- 读取本机已保存的图片模型、接口与 Keystore 加密 Key，使用百炼 [Z-Image 同步接口](https://help.aliyun.com/zh/model-studio/z-image-api-reference)，请求一张 `768*768` 图片，`prompt_extend=false`。本地只根据任务标题构造装饰提示词，不额外调用语言模型，也不发送详情、聊天、文件名、附件内容或用户图片。提示词与模型名随本地媒体元数据保存，实际模糊、文字底色和完成态仍由界面绘制。
- 使用 [WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent) 处理有网络约束的唯一后台工作；队列、生成中、下载中、成功、失败和被用户图片替代等业务状态保存在主库 `schedule_cover_jobs`。会话与详情显示进行中状态，成功后卡片自动淡入图片；失败显示原因，支持“重新生成”或“重试下载”，已保存日程继续可用。
- URL 仅用于临时下载，使用独立 HTTPS GET，不携带 API Key，不跟随重定向，限制下载大小。图片验证为 768×768 后复制到应用持久原图目录，元数据、任务所有模板／发生封面和成功状态原子提交；成功后清除临时 URL。日常渲染只读取本机文件，重启和断网仍可看图，AI 封面不计为用户附件。
- 每个生成尝试有唯一标识，重复发送、重复调度和页面重开不再次生成。改时间、日期、补充文字、完成和展开周期均不自动重做封面。周期所有发生只共享一张本地封面，包括生成前已展开的记录和以后展开的日期。
- 生成结果拿到 URL 后先持久保存，再开始下载；下载失败最多自动重试两次，仍失败可手动继续下载，有效地址不重新生成。关闭页面不取消工作；进程重启可恢复已登记队列与有效 URL 的下载。如果进程在生成请求后中断且没有收到 URL，结果未知，不自动重复 POST，显示已中断并由用户决定重新生成。过期 URL 不被当作有效封面，显式重新生成才发起新请求。
- 用户在生成或下载中上传／选择图片，会在本地事务中停止该任务封面工作的接管资格；迟到结果不能覆盖用户图片，即使后来又移除了该图片。删除整个任务级联清理工作记录，迟到下载不会重新创建任务；无引用的落地图片按既有队列清理。单次周期删除不影响其他发生的共用工作。AI 图片赋值失败整体回滚，不留下半条封面关联。
- schema 5 → 6 只新增封面工作表和索引，不清理旧业务数据或媒体文件。

- 分页只订阅并保留当前、前一天、后一天三日的本地内容；相邻日期切换可立即使用预读结果，滚到更远日期后释放旧窗口。每一页使用自己的纵向列表状态，完成重排继续保留视口；完成、改期和删除会同步更新预读页，旧日期结果不覆盖新日期。

## 图片

内置封面通过数据库中的稳定 key 映射 APK 内的 640 × 640 WebP；用户导入及 AI 生成封面按数据库相对路径读取 `filesDir` 中的持久文件，图片选择在 0.10.0 接入，0.11.0 在新建成功后调度无用户图片任务的生图。读取前校验路径范围，后台解码到最长边不超过 1024 像素，以 12 MiB 的有界缓存复用，不发出图片网络请求、不修改原图。无封面、未知内置 key、文件丢失或损坏时使用卡片底色与日历占位，文字、详情与完成操作仍可用。卡片图片与文字各占独立区域，图片不叠加模糊、渐变或分隔线；详情与全屏预览直接读取相同本地文件。旧 AI 图若已包含模糊像素，可按“完整画面 AI 封面”一节手动重新生成。

素材路径、内置 imagegen 的完整生成提示词见 [配图记录](schedule-image-prompts.md)。

## 新建草稿（0.4.2，0.12.0 更新入口）

- 日程页底部常驻输入栏，不提供独立的会话列表、草稿列表或对应弹窗。进入页面后自动恢复最近一次未完成的新建会话，含已发送文字、未发送输入与待补充问题；没有时创建一份空会话。尚未生成任务时，输入发送完毕也不视为日程创建完成，再次打开仍继续原会话。
- 浮层顶部提供“清空”按钮，一次点击即丢弃当前新建草稿并创建全新 sessionId，移除旧会话的文字、消息、追问及附件关联。清空不需要先保存正在输入的文字；失败时事务回滚，界面保留原内容并可重试。清空和发送期间禁用重复操作。
- 首次打开新建时，在数据库中选择最近编辑且含内容的未绑定任务会话；若仅有空白会话则复用。旧版本遗留的其他未完成会话在同一事务中清理。之后始终只保留这一份新建草稿，关闭、旋转和无 SavedState 的应用冷启动均从本地记录恢复。
- 未删除任务的会话、周期规则和每天的卡片继续保留；0.8.0 明确删除任务后，会话与全部历史也随之移除。新建入口不复用它们；清空不删除它们；0.10.0 会清理被丢弃草稿中无人引用的应用附件副本，保留其他任务共用文件和用户相册原件。周期任务所有发生卡片仍通过 occurrence → task → session 关联同一任务会话。0.6.0 的真实详情提供“继续会话”，始终打开原任务会话。
- 0.12.0 的对话浮窗宽度与右侧输入框外框一致，常规竖屏约占可用窗口高度 75%；输入框留在窗外。空白内容不可发送，支持键盘发送。关闭按钮、遮罩和系统返回可收起浮窗，使用位移与淡入淡出；详情继续保留原生可拖动底部弹层。
- 输入使用 180 毫秒防抖，关闭或正常重新进入前立即提交，后台写入串行执行。只有数据库提交成功才显示已保存；版本冲突保留当前文字，明确点击“保留当前文字”后才重试覆盖最新草稿。
- 发送先保存当前输入，再通过事务写入消息并清空输入。失败保留原文，同一消息 ID 重试不重复入库，也不清掉后来补充的文字。初始读取最近 40 条消息，可查看当前会话更早记录，不删除分页窗口之外的消息；离开日程页或应用进入后台停止订阅，收起聊天窗后底栏仍可输入；已开始的保存不因后续输入取消。
- 待补充问题及其答复单独持久化；用户发来普通回复不会自动解决全部问题。0.7.0 由模型提取明确已答复的问题 ID，经本地同会话、消息先后校验后保存答复，并生成追问或日程。0.10.0 接入附件选择，0.11.0 接入 AI 封面，系统响铃后续接入。
- 0.4.2 的单份草稿收敛没有改动 schema 2；其后的模型配置使用 schema 3，0.7.0 继续保持 schema 3。schema 1 → 2 → 3 迁移保留既有任务和历史，新建草稿收敛在打开新建入口时执行。

## 详情中的任务说明

详情弹窗按“标题 → 日期时间与附件 → 分割线 → 图片 → 本地已保存的 `detail` → 分割线 → 删除／编辑／完成”展示。标题、日期与附件位于顶部，图片和任务说明构成独立的可滚动内容区，底部操作固定可见；两条分割线随主题配色。说明由模型在创建或编辑时根据当前任务会话的用户文字整理，保留具体对象、数量、地点、原因和准备事项；后续补充合并，更正时替换被纠正的旧表述，未修改的信息继续保留。标题最多 30 个 Unicode 字符，任务说明不受标题字数限制，不展示 AI 执行回复或臆测附件内容。

日期时间与附件统一使用 11 sp 字号、16 sp 行高，日历／附件图标分别为 14／13 dp；标题到信息行的间距及信息行下方留白均缩至 4 dp。附件按钮可见布局最小高度为 28 dp，系统最小触控区域仍由 Compose 扩展，字体放大时布局可以继续增高，避免固定高度裁切。手机验收时检查信息行更小、更紧凑，带附件任务仍能点击数量打开附件列表，大字体下日期和附件内容完整可见。

说明使用小于标题的 14 sp 正文、21 sp 行高和主题次级文字色，可自然换行；空说明不占位。长说明沿用详情内容区滚动，底部“删除／编辑／完成”始终可用。直接读取任务发生记录，打开详情不重新调用模型、不遍历聊天记录；历史任务已有说明立即可见，主界面和聊天中的小卡片继续保持紧凑。

手机验收：

1. 打开已有带备注、原因或采购物品的任务，标题和日期附件在顶部，第一条分割线下先图片后说明，第二条分割线下为操作按钮；关闭后断网重开，内容仍可查看。没有图片或说明时直接省略对应内容。
2. 新建“后天晚上10点提醒我重置 Codex 额度，因为有一张重置卡”，详情应包含行动和重置卡信息；从“编辑”补充、更正后返回，显示最新保存的说明。仅改时间后，原有说明应保留。
3. 查看多行长说明，并切换亮暗主题、大字体或横屏：内容可滚动，日期、附件入口和底部三个按钮仍可用；图片预览、完成／恢复及返回关闭保持原行为。

## 已完成分区与最近完成优先

日程页面继续使用同一个双栏网格和每页独立滚动状态，上方展示未完成任务；有已完成任务时，插入横跨两列的主题色细线及居中“已完成”文字，再另起行展示已完成任务。未完成任务数量为奇数时，不会把完成任务混进同一行；全为已完成时从分割标题开始展示，没有已完成任务时不显示空分区。

已完成组使用原有发生记录的 `completedAt` 倒序，刚完成的卡片排在组内第一张；仅日期任务与准点任务同样按完成时间比较。取消完成后回到上方原有提醒排序，再次完成后使用新的完成时间回到组首。时间戳随数据库查询和完成提交同步进入页面、预读页与详情；切换日期和重启后顺序保留。沿用卡片及分割标题的移动／淡入淡出，完成与恢复保持当前视口。

本次仅调整既有字段的查询和展示，无数据库结构或迁移变更。开发机测试覆盖真实 Room 查询、反向输入后的页面排序、完成／恢复／再次完成、数据库关闭重开及页面与详情时间戳一致性。

手机验收：

1. 查看同时有未完成、已完成卡片的日期：上方仅未完成，分割线下方仅已完成；未完成为奇数张时，分割线仍独占整行。
2. 依次完成两张卡片，后完成的一张应位于已完成组最前；从详情完成也应遵守同一顺序。取消最新一张，再完成，它应重新回到组首。
3. 切到其他日期再返回、重启应用，完成时间排序保留；无已完成时不显示空分区，全为已完成时仍能清楚看到分组标题。
4. 检查长列表滚动、左右切换日期、亮暗主题及大字体；原有灰色完成样式、未完成粗黑文字和完成／恢复交互保持正常。

## 未完成与已完成卡片底色

未完成日程卡片的信息区恢复为主题表面色，当前亮色主题下为原来的白色；已完成卡片保留原有信息区底色、灰色文字与“已完成”标志。完成或恢复时，底色沿现有 260 毫秒过渡切换。主列表与聊天中的日程结果共用卡片，深色主题继续使用对应的主题颜色；未完成／已完成通过独立分区和分割线区分。

手机验收：未完成卡片的标题／日期区域应恢复白色；完成后移到分割线下方，恢复后回到上方白底未完成组。列表和聊天卡片都应同步，图片与附件数量保持可见；切换深色主题后，分组与文字仍清晰。

未完成卡片的标题与日期／时间采用 Bold 字重，亮色主题下为黑色；深色主题使用主题正文亮色。完成后仍沿用原有灰色与字重（标题 SemiBold、日期 Normal），恢复后重新变为较粗的高对比文字。字号、单行省略与日期自适应缩放保持原规则。手机验收时同时检查仅日期与带时间卡片，以及完成／恢复和聊天卡片的显示。

## 最近图片首次加载修复（0.21.4）

首批照片已读取后，旧逻辑在退出加载态前调用 `scrollToItem(0)`。该调用等待网格首次布局，但加载态只显示转圈，网格尚未进入布局，于是两边互相等待，面板会一直转圈。问题位于展示流程，减少读取数量不能解除等待。

现在先发布图片并退出加载态，顶部定位使用 `requestScrollToItem(0)` 请求下一次布局处理，不等待尚未挂载的网格。用户在顶部时展示最新照片；浏览旧图时保持位置。行为依据 [AndroidX LazyGridState 源码](https://github.com/androidx/androidx/blob/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/lazy/grid/LazyGridState.kt)，无需新增依赖。默认三行、每次再加载三行、媒体变动刷新及已选序号继续保留。

回归测试使用真实 `LazyGridState`，刻意不挂载网格，在同一条件下旧逻辑会等待超时；修复后首批及最新照片的定位立即返回，浏览旧图的偏移保持不变。已有媒体查询、权限与新增／修改／删除监听测试继续执行。

手机验收：

1. 重新进入日程并点击加号，首批图片应显示，不再一直转圈。收起、展开数次应仍能加载。
2. 默认三行后点击“加载更多”，应增加三行；先选图再加载，已选序号和输入内容保留。滚动浏览旧图后切后台再返回，不应跳回顶部。
3. 从相机或相册返回后能继续选图；最新照片自动刷新。闪念共用的加号图片面板也应能首次加载。

继续保留最新图片自动刷新、已选序号、输入内容及当前浏览位置，日程与闪念共用面板同步生效。手机验收：打开加号后向下滚动，默认应在第 3 行后出现“加载更多”；连续点击两次依次扩展到 6 行、9 行；到底后按钮消失。加载前先选图，追加图片后检查选择仍保留；关闭再展开应恢复默认 3 行。

## 最近图片刷新（0.20.3）

1. 用手机相机新拍一张照片，返回日程点击加号，新图应在快捷图片列表最前面，不必进入“相册”。
2. 保持加号面板打开，切到相机再拍一张并返回；相册扫描完成后应自动出现。多次收起、展开面板检查顺序一致。
3. 选择几张图片后浏览更早图片，再返回前台或加载更多：输入内容、已选序号和当前浏览位置不丢失；使用相册／文件入口及闪念面板仍能正常导入。

## 完整画面 AI 封面（0.20.2）

原有生成提示词仍要求“主体位于画面上半部，下半部留背景供叠字”，已不适合图片和文字分区的卡片，导致模型将模糊留白直接画进原图。本版改为单一连续、主体完整居中、全画面清晰的写实摄影场景，明确不要上下分区、拼接横条、局部模糊、渐变遮罩或叠字留白。仍使用 768×768、`prompt_extend=false`，只发送根据标题构造的提示词。旧队列在真正发起生成前刷新提示词；已有 URL 的下载不自动重新请求生成。

现有图片中的模糊内容已属于文件像素，修改提示词不会让旧图自动恢复。在 AI 封面的全屏预览中，左下角提供“重新生成封面”，显式点击后才登记新的生成请求，不批量重新生成历史图片；用户照片继续采用原有封面与移除操作。生成中按钮显示状态并防重复，失败可重试，有效 URL 优先继续下载。

重新生成期间保留当前封面，新图下载校验后事务更新该任务、模板与所有周期发生的封面引用；之后才清理无其他引用的旧 AI 图片。失败不删除旧图。用户上传图片、选择用户封面或删除任务后，迟到结果仍不能覆盖用户选择或恢复任务。预览、卡片和详情直接显示相同的本地图片，界面不增加模糊或图像分隔线；文字区继续使用独立主题底色。

手机验收：

1. 新建无用户图片的日程，待封面生成后查看卡片、详情和全屏预览；画面应连续完整，无人为预留的下半幅模糊带或上下拼接。
2. 打开已有“钓鱼”等旧封面，进入全屏图片预览，点击左下角“重新生成封面”。生成期间仍显示旧图，成功后各处使用新图，日程时间、完成状态、附件及会话保留；同一周期各天同步更新。
3. 在重新生成时断网或关闭预览，再返回检查状态与重试，旧封面仍可用；重复点击不重复登记。期间上传用户图片或删除任务，迟到结果不能覆盖或恢复。用户照片的左右翻图、设置封面及移除继续正常。

开发机验证使用模拟模型与真实 Room／本地图片：覆盖旧队列提示词刷新、替换成功前保留旧图、周期共享更新、重复请求、旧图共用引用保护、失败后仅重试下载、用户图片优先和删除后的迟到结果。实际模型出图质量由用户手机验收，不在测试中发起付费调用。

## 日期栏先行切换（0.18.3）

点击日期时改为先定位日期栏、后切卡片页。点击后立即采用目标日期的选中反馈和月份，日期栏用约 160 毫秒居中到目标日；随后卡片页沿用约 260 毫秒翻页。卡片页切换期间，上方日期栏保持在目标日，不再被下方仍在滑出的旧日期带回；卡片停稳后才提交实际业务选中日期。两段动画直接衔接，不额外等待。

直接滑动卡片页继续让日期栏同步跟随。连续点击会从当前日期栏位置重新定位，卡片已在移动时同时平滑转向，避免停在半页再重复等待；开始手动滑动卡片或日期栏时取消尚未完成的点击请求，旧请求不会再提交日期。两段过渡遵循系统动画设置，关闭动画时直接完成切换。0.18.1 的目标日预读、滑出页保留及临时窗口回收继续保留。

手机验收：

1. 点击相邻日期，检查上方日期先居中并选中，随后下方卡片切换；期间日期栏不回跳。点击跨月日期，月份也应先显示目标月份；到达后日期与卡片内容一致。
2. 直接左右滑动卡片，日期栏仍同步移动。点击后立刻手动滑动卡片或日期栏、连续反向点击，检查能从当前进度接管，无旧请求回跳和残留加载。
3. 在有图、多任务与空日期之间切换，确认不先清空滑出页；详情、完成／恢复和日期圆点保持正常。关闭系统动画时应直接切换，不保留人为等待。

## 日期点击与手势统一（0.18.1）

此前点击日期直接提交选中日期，立即收缩页面缓存并重启数据库订阅，之后才由页面监听发起翻页；手势则在停稳后才提交日期。点击时的数据更新可能与翻页的首帧重叠，较远日期还可能提前释放滑出页。本版让日期按钮直接驱动已有 Pager，沿用 260 毫秒过渡，与日期栏共用进度；动画停稳后再提交实际选中日期，避免动画前先切数据。

- 相邻日期沿用现成的三日缓存，不在点击时更新页面状态或重启订阅。未预读的目标只临时增加目标当天，最多保留当前及前后一天加目标日，共四天；周期也只补充展开该目标日，不展开整段间隔日期。滑出页保留到过渡结束，提交后恢复正常三日窗口。
- 连续及反向点击使用最新请求，旧协程不能提交过时日期或取消新请求的保护状态。用户从内容区接管滑动时，保留正在露出的目标页，手势停稳或取消回原页后再释放临时预读；外部实际选日（如创建后定位、通知定位）会取消旧的点击导航。
- 月份、日期居中位置和选中反馈继续跟随同一 Pager；圆角按压高亮、过去／今天／未来层级和阴影保持原样。本轮只改变导航时序与临时预读，不修改已保存日程、附件、响铃状态或数据库结构。

开发机验证：真实 Room 验证相邻日预读复用原状态、远日预读保留滑出页且只增加目标一天、提交后立即使用缓存并回收临时窗口、快速替换与取消目标不显示陈旧数据，以及周期不展开整段日期。导航请求测试覆盖替换取消、旧请求迟到结束与外部定位取消；原有页面及提醒测试同时通过。实际帧率和触控手感由用户手机验收。

手机验收：

1. 在有多张卡片的日期与相邻空日期之间反复点击日期按钮，与内容区左右滑动对比；点击应直接进入平滑翻页，滑出页不先变空或闪加载，日期栏与内容同步。
2. 连续点击前后日期、动画中反向点击，再用手指接管滑动或取消手势；最终日期、月份、卡片内容一致，不被旧请求拉回，不残留加载状态。
3. 横向浏览日期栏并点击较远日期，目标日按需加载；返回有任务日期后，图片、完成状态、日期圆点和滚动正常。检查任务创建后定位和通知打开详情仍能到正确日期，详情及响铃提示正常。

## 详情弹窗即时展开（0.15.1）

点击卡片时立即传入已显示的日程，优先从当前日及预读相邻页取得卡片快照；聊天结果卡片也使用点击时的快照。首帧直接显示图片区、标题、日期及操作，不先创建短小的加载占位再替换为详情。附件按同一会话立即开始订阅，数据库查询在后台继续校验和更新；一旦确认任务不存在或读取失败，不再用旧快照恢复详情。

原生底部弹层首次测量直接使用展开锚点，以同一段 220 毫秒过渡驱动 28 dp 短距离上移、透明度和背景遮罩渐暗，取消默认从整屏外滑入造成的遮罩先行观感。入场期间不叠加 220 毫秒的内容高度动画，入场结束后的内容变化仍平滑调整。保留原生下拖、外部点击、返回和预测返回关闭，以及关闭详情后编辑原会话的行为；动画继续遵循系统动画时长设置。

详情和全屏图片请求较大位图时，首帧可先显示列表缓存中的同源缩略图；后台加载完成后替换为较大位图，不等待解码才显示弹窗。原图、任务及附件记录不修改，仍按来源和尺寸隔离缓存。

开发机验证覆盖相邻页卡片即时作为详情初值、聊天快照过渡、数据库删除或失败不回退旧内容，以及缩略图先显示后仍能读取真正的大图；页面与附件相关测试同时通过。手机上的首帧、动画和手势体验由用户验收。

手机验收：

1. 重开日程页，分别首次点击有图、无图和多图卡片，再关闭并重复打开：详情应直接出现并短距离上移，遮罩同步渐暗，不再先出现灰幕再等待弹窗，图片加载不阻塞标题和按钮。
2. 点击外部、系统返回及下拖分别关闭，连续打开不同卡片，检查没有旧任务内容闪现、闪屏、遮罩残留或卡住。聊天中的结果卡片也应立即打开正确详情。
3. 打开图片全屏浏览后返回详情，再点完成／恢复或编辑，确认按钮与原会话正确、删除文字仍为红色；亮暗主题、大字体和系统关闭动画时检查内容、遮罩及关闭操作正常。

## 日期切换性能（0.14.15）

日程列表继续使用双栏懒加载，只组合可见和附近卡片，并预读相邻日期的本地数据。本轮代码检查发现小卡片仍按 1024 像素上限解码图片，与全屏图共用 12 MiB 缓存，多图或浏览大图后容易重复解码；翻页还额外合成了整页透明度，页面重组也会再次排序已经排好的日程。没有在手机上测量帧率，不将这些静态发现等同于已确认的全部卡顿来源。

- 列表和聊天结果卡片改按实际像素宽度选择 256／512／768 像素上限，原图保留，只有显示用的位图缩小。缩略图使用 12 MiB 有界缓存，详情和全屏大图使用单独的 8 MiB 缓存，超过缓存容量的大图只供当前界面持有，不挤掉缩略图。
- 小图、大图分别串行解码，后台读取、校验路径、处理方向并准备位图；相邻页及周期卡片对相同来源、相同尺寸复用解码结果。清理缓存后，之前已经开始的解码不能将结果重新写入缓存；改变封面来源时重置该来源的图片状态，避免先显示旧图。旋转产生新位图后及时释放中间位图。
- 保留原生分页跟手、吸附、回弹和日期同步，去掉整页透明度叠加，减少翻页合成开销。列表直接使用数据层已排好的日程，预览回退列表仅在内容改变时排序。卡片阴影、完成动画、日期大小层级与业务顺序保持原样。

开发机验证：使用真实位图和本地文件验证十张封面的缩略图在全屏预览后仍能复用、不同周期发生共用解码结果、原图字节不变，以及清缓存后不再读取已移除文件；同时运行日期页面、附件、封面和 Android 8 兼容相关测试。测试不向手机写入日程数据，实际滑动体验由用户验收。

手机验收：

1. 在任务较多、带多张照片的日期，先上下滚动，再分别点相邻日期和较远日期返回，连续重复数次；检查翻页停顿是否减轻、封面是否完整，日期与卡片仍同步移动。返回首页后重新进入也对比一次。
2. 打开其中一张图片全屏浏览，返回详情后关闭，再切走并返回多图日期；列表不应因为刚看过大图而重新逐张闪出占位。大图仍可清晰查看、左右翻图、设置封面，列表仍保留阴影和紧凑等高布局。
3. 完成／恢复、改期、删除任务及移除图像后重新切换日期，检查状态、排序、日期圆点及封面正确；重启后本地图片仍可显示，已删除内容不恢复。

## 紧凑卡片与日期阴影（0.14.13）

- 卡片下方空白来自日期、时间与附件区统一预留的第二行。本版收紧为一行：标题使用 13 sp 字号、18 sp 行高，超出可用宽度显示省略号；新建与改名最多 30 个 Unicode 字符，原有标题不改写。日期、分钟级时间与附件数量横向排列，日期时间字号根据可用宽度在 8～11 sp 内适配，统一保留 15 sp 行高；信息区仅保留上下各 8 dp 内边距和两行之间 4 dp 间距。卡片继续按宽度与系统字体统一计算高度，不因标题长度、有无时间或附件而变高，列表与聊天结果复用相同布局。
- 上方日期卡片沿 13 dp 圆角增加模糊半径 4 dp、向下偏移 2 dp 的柔和阴影，过去日期较轻，今天更突出，未来日期居中；亮暗主题分别调整强度。日期栏额外预留 10 dp 垂直空间容纳阴影，视觉卡片大小层级保留，阴影位于内容裁剪之外，按压高亮裁成实际卡片圆角。可点击范围至少 48 dp，日期栏继续直接跟随卡片分页进度。

手机验收：

1. 同一天查看短标题、30 字符标题、带时间和带附件的卡片：标题始终一行，放不下显示省略号；日期、时间和附件数量在一行内，底部没有额外一行空白，双栏保持等高。检查聊天中的结果卡片也采用同样的紧凑样式。
2. 检查过去、今天和未来的日期卡片均有自然阴影，过去日期仍灰且小，今天更大，未来中等。点击日期的瞬间仍是圆角高亮，内容区左右滑动时日期栏同步移动，连续切换不出现阴影残留或卡顿。
3. 完成／恢复日程后，文字灰显、排序和高度保持一致；切换亮暗主题及放大系统字体后，标题仍单行省略，日期信息不换行撑高卡片，日期按钮可点击且不裁切文字。

## 临时日程详情（0.14.11）

详情改为按内容收紧的临时底部弹窗，保留原有圆角阴影、拖动关闭、系统返回及外部点击关闭。移除“日程详情／本地／关闭叉号”顶部栏、周期说明块及底部附件添加工具栏；任务说明位于分割线后的内容区，原始详情、周期、附件与会话继续保存在本地。

弹窗随内容平滑展开，无图时缩短；大字体与横屏下内容区域可滚动，底部三个动作保持可用。全屏图库关闭后回到详情，不连带关闭详情；只有任务附件才能执行封面与附件移除，历史及装饰图片不伪造附件引用。

- 待发送附件与历史附件分开。取消新导入且未发送的附件可清理无人引用的副本；重新选择已发送文件再取消，只取消本次发送，保留既有日程封面与历史。任务详情仍可管理全部任务附件；从任务中移除已发送文件后，历史消息继续持有本地副本并可预览／打开。删除整项任务或清空未完成会话时才一并清理其消息引用和无人引用的文件。
- 消息附件按当前消息分页窗口查询，读取更早聊天时再加载对应元数据。模型上下文继续只包含当前任务会话文字及结构化日程；顶层 `attachment_summary` 是当前任务附件总数，每条消息另有本次附件数量／图片数／文件数。均不包含文件名、路径、URI、图片编码或文件内容，不上传媒体。
- 主库 schema 6 → 7：`schedule_local_attachments` 增加待发送与仅草稿标记，`schedule_attachments` 增加批次内顺序与显示名称；已有任务、原图、会话、草稿、封面工作和加密凭据均保留。旧版已保存任务的图片不重新预填到输入区，未完成新建草稿继续恢复所选内容。旧版没有保存消息关联的图片仍在任务附件里，不编造为过去某条消息的发送记录。

手机验收：

1. 点击输入框左侧加号，面板应显示相机、相册、文件和最近图片区；首次允许全部照片或部分照片访问，检查网格只显示可访问内容；拒绝后仍可从相册／文件入口选择。收起再展开、切后台再返回不应崩溃或显示无效缩略图。
2. 从网格／相册选择两张图片和一个文件，内容应横排在输入框上方，逐项叉号只取消对应选择，相册原件不受影响。点击文字区弹出键盘并收起媒体面板，输入和发送保持可见。
3. 输入“明天处理这两个图片的事”并发送，预览从待发送区清除；聊天中该条用户消息保留图片／文件和文字，AI 只依据文字及数量／类型回复，日程卡片可打开，用户图片优先作为封面。
4. 继续只发送“改成后天”，新消息应只有文字，上一条图片不重复出现在新消息。关闭、重启后从详情继续会话，原图片和文件仍能预览／打开；文件本地副本不依赖源文件继续存在。
5. 用新草稿只发送图片，应先显示图片消息并询问要安排什么活动；再补充文字，只创建一项任务，不追问图片里是什么内容。断网发送后保留消息，手动重试不重复发图或建卡。
6. 点击相机，拍照确认后在输入框上方出现图片；取消拍照不增加附件。选择器／相机中切后台、旋转重建及返回后，结果不能加到另一项任务。
7. 清空草稿后重启，旧待发送图片不能恢复；已保存任务保留。取消重新选择的旧图片，原任务封面与聊天历史应保留。整项删除仍按原规则删除任务、聊天和不再使用的应用副本。
8. 检查亮色／暗色、放大字体、键盘与加号面板交替展开、聊天窗开合；日期同步切换、完成／恢复和周期任务的原会话关联仍正常。

## 日程输入与对话浮窗（0.12.0—0.13.0）

当前布局依据用户确认的 双状态框架图；此前视觉参考见 初版浮窗布局。

- 底部是左右各留 16 dp、铺满可用内容宽度的空白输入框，右侧保留 48 dp 发送圆钮。点击输入框，光标直接进入并弹出键盘；点击输入不会自行展开聊天。最多三行文字，支持键盘发送，导入及消息处理期间防止重复发送。

- 图片框右上角的小叉号保留 48 dp 触控区，小圆形标记中心贴合角点，并预留空间避免裁切。点击可直接移除对应图片，点击图片继续预览或切换封面；已有任务的文件仍在详情管理。
- 图片选择器注册在页面，附件状态按当前详情或当前会话绑定；系统选择器重建和迟到结果继续通过原会话 ID 处理。图片仍复制到本地，移除只影响应用副本／引用，不删除相册原件；模型仅获取数量与类型。
- 未完成的输入、已发送消息、追问及图片恢复到唯一草稿；收起未完成对话后，底栏的“继续对话”可查看历史，也可继续输入发送。关闭已保存任务的对话后，底栏回到新建草稿；在途解析先完成保存，再切换，避免关闭导致请求被取消。详情“继续会话”仍进入所选任务／周期的原会话。清空会创建新会话，已保存任务与其历史保持保留。

附件指代规则增加 `attachment_usage=user_reference_only` 的请求标记，用户的“做／处理／完成图片或附件里的事”就是可保存活动。示例“今天晚上要做这两个图片的事”直接保存当天仅日期日程，标题可为“处理图片事项”，详情保留晚上及附件指代，不推测图片内容或具体提醒时刻。模型若仍输出要求解释附件内容的追问，本地返回解析结果无效，保留原消息与图片供手动重试，不自动追加收费请求；必要动作、提醒时刻及明确识别附件需求的文字追问继续允许。成功创建／编辑时，本地可将旧的无须内容追问作废，即使模型遗漏对应 ID；历史消息保留。

## 本地数据基础（0.4.0）

数据库与文件接口自 0.4.0 起注册在 Application 的 AppContainer 中，按需创建，0.6.0 接通真实日程页面，0.7.0 接通 AI 创建。不植入示例业务记录，系统闹钟登记在后续接入。

### 已确定的业务规则

- 一个会话最多对应一项任务，包括一整项周期任务；会话内通过固定关联完成增删改查，不让模型从多项任务中猜测目标。创建前的消息及图片也可先保存。整个任务删除后连同会话移除，不将被删除的会话重新用于另一项任务。
- 新标题去掉首尾空白后为 1～30 个 Unicode 字符，不截断用户输入；过长、空白或无效参数会在本地拒绝，事务不产生半条记录。升级前已存的标题保留完整内容，其他字段修改不强制改名。
- 未指定日期时按设备当天保存；明确指定日期则保留。仅日期任务的时间为 null，不伪造 00:00，不创建定时提醒。时间精确到分钟，不采用旧版宽泛时段。
- 有明确时间的任务默认提前 10 分钟和准点提醒。提醒配置是去重后的非负分钟数，0 代表准点，正数代表提前量。用户指定提前 8 分钟时保存 `[8, 0]`。显式空列表关闭提醒。已经过去的提醒记录为 MISSED，不作为待触发提醒。
- 支持每天、每周指定星期、每月指定日期、间隔若干天的周期规则；支持结束日期和启停。月规则遇到不存在的日期时跳过该月，例如每月 31 日不自动改成 2 月末。
- 一项周期任务的每次发生有独立 ID、完成状态和提醒记录。规则按用户查看或调度所需范围展开，每次最多一年，使用唯一键避免重复；不一次性生成无限未来记录。
- 周期模板的后续编辑默认从所选原发生日开始（不早于设备当天），也可指定起点；保留已完成及过去的快照。旧版本的标题、时间、规则和提前量也以结构化记录保留，后续浏览未展开的历史日期仍能按当时版本生成。普通任务的显式编辑移动或修改同一张卡片，并保留修改版本和操作记录。

### 数据表与关联

主数据库名称为 `mebot.db`，由各 Bot 共用，不为日程另建私有数据库。

| 表 | 保存内容与约束 |
| --- | --- |
| `schedule_sessions` | 会话及创建、更新时间 |
| `schedule_messages` | 用户／助手消息；会话内顺序号唯一，避免同毫秒消息错序 |
| `schedule_conversation_drafts` | 会话输入草稿、保存版本及更新时间，sessionId 唯一 |
| `schedule_pending_questions` | 待补充问题、回答消息及解决时间 |
| `schedule_tasks` | 一项逻辑任务；sessionId 唯一，包含当前标题、详情、日期、时间、封面及版本 |
| `schedule_task_versions` | 不可变的模板版本与生效日期 |
| `schedule_recurrences` | 各模板版本的周期规则 |
| `schedule_reminder_leads` | 各模板版本的多次提前提醒配置 |
| `schedule_occurrences` | 实际日程卡片快照；任务与发生键唯一，关联正确模板版本 |
| `schedule_reminders` | 各次发生、版本和提前量的提醒记录；记录触发时间、时区和执行状态 |
| `schedule_occurrence_leads` | 单次例外卡片的独立提前量 |
| `schedule_exclusions` | 仍生效的周期中排除的发生键，不保留被删卡片内容 |
| `media_cleanup` | 事务提交后待清理的无引用文件路径，清理完成即移除 |
| `schedule_cover_jobs` | 每项任务的一次封面生成／下载状态、尝试标识和临时恢复信息，删除任务时级联清理 |
| `media_assets` | 内置／导入／AI 生成媒体与普通文件的元数据、本地文件引用；内容哈希唯一 |
| `schedule_attachments` | 旧版消息附件关联，升级保留 |
| `schedule_local_attachments` | 会话级附件、显示名称、选择顺序和封面标记；不必先发送文字 |
| `schedule_operations` | 请求 ID 去重、操作顺序及前后快照，用于追溯，不作为当前业务状态来源 |

创建、编辑、完成和删除均在 Room 事务中写入相关表。请求 ID 及内容指纹防止同一次请求重试后重复执行；编辑检查版本，拒绝覆盖已经改变的内容。明确删除任务会物理移除任务、提醒、会话和历史，不保存删除快照；完成只取消待执行提醒。仅删除周期某次时移除对应卡片与提醒，保留其他日期共用的会话。按日期及日期范围查询，保持“未完成具体时间升序 → 未完成仅日期 → 已完成”的排序。历史分页读取，不在启动时全量加载。

日期保存为 epoch day，时间保存为可空的分钟数；创建、修改、完成和提醒触发时间保存为 UTC 毫秒。提醒时间由设备时区换算，并记录换算时区；未来接入调度器时需在设备时间／时区变化后重建尚未执行的提醒。PENDING 仅表示等待调度，SCHEDULED 必须在后续 Android 调度器成功登记后设置；本轮没有实际发出通知。

### 图片与容量

- 装饰封面和用户附件共用图片资源元数据，以关联关系区分用途。内置封面保存稳定 key，不保存可能随构建改变的 drawable 整数 ID。
- 用户图片、下载图片和 AI 生成结果通过流复制到 `filesDir/media/originals/`，按 SHA-256 分目录保存，不将图片二进制或 Base64 写入日程表。AI 来源可保存生成提示与服务标识，不保存服务密钥。
- 先在同一文件系统的 staging 中写完整文件并同步，再重命名，最后保存数据库元数据。正常中断清理临时文件；文件完成后数据库写入失败可能留下完整孤立文件，重试可复用，不能为清理而误删仍有引用的文件。
- 同内容图片共享文件与资源 ID；用户附件原文件保留。导入检查实际图片格式及尺寸，单张限制 50 MiB，复制和读取在 IO 线程完成。0.6.0 真实页面按需读取与缩小解码，不生成额外持久缩略图；后续派生文件缓存仅放在 `cacheDir/media_previews/`。
- 缓存清理不触碰正式图片及数据库；整个任务删除会清理不再被任何记录引用的图片副本，共用图片继续保留。后续永久清理、备份与导入应同时处理数据库和文件的一致性。
- 按每天 2～3 条计算，一年约 730～1095 条日程。若每条均使用独立的 200 KB 封面，封面约占 146～219 MB／年，属于估算，未包含附件原图与缓存；复用内置封面不会按任务重复占用图片文件。

## 手机验收

下列较早版本的用例保留用于回归；0.12.0 中“新建日程”操作改为底栏直接输入并发送，“文件”选择改从详情进入。当前布局以“日程输入与对话浮窗”章节为准。

本机无真实任务时，先按下方“自然语言创建专项验收”创建任务，再验证卡片、圆点和完成状态。助手不向手机植入测试记录，不代替用户操作手机验收。

1. 首页打开侧栏，点击日程卡片：侧栏平滑收起，首页切换到日程页，日期栏中间是今天；无记录时显示空状态，不出现旧示例及虚假圆点，有记录时展示当天真实任务。月份后没有“示例”。点击房屋图标返回首页，再进入仍默认定位今天。
2. 点击前后两天：选中样式、日程内容及月份标题正确变化；左右连续滑动日期栏可以浏览更远日期，不拉动侧栏。点击无圆点日期出现空状态。
3. 检查卡片日期不含年份；带时间日程在通常字体下显示月日时分。检查右上角圆圈没有外扩白边，点击后显示主题强调色与清楚的勾号，照片平滑变灰，再次点击恢复；按钮点击不打开详情。带时间卡片的闹钟为橙红色，仅日期卡片无闹钟。特别检查家庭聚餐、项目复盘等卡片的文字背后能透出照片的色彩与模糊轮廓，标题与日期清晰可读；完成／恢复后也保留图像细节，放大字体及暗色主题下仍覆盖全部文字。
4. 点击卡片正文打开详情：圆角周围出现柔和外阴影，弹窗与后方卡片有清楚的层次；在亮色与暗色主题下分别检查。滚动查看内容，在详情中切换完成状态后关闭：列表同步显示。测试关闭按钮、遮罩、向下拖动和返回，特别检查阴影随弹窗移动，连续开关与拖动取消时不脱离、不残留。
   排序与持久化专项：未完成的带时间任务先按时间升序，随后为仅日期任务，再是已完成组。将最早的任务标记完成，它应平滑移入末尾，视口不跟着跳动；恢复后回到时间序列首位。对仅日期任务、详情浮层中的完成操作、切换日期返回分别检查同一排序规则。标记完成后从最近任务划掉应用再重开，切回同一天，状态仍应保留，该日期仍有圆点。周期任务不同日期的卡片只独立切换当天完成状态，通过详情“继续会话”则打开相同消息历史。完成标志专项：完成后灰色“已完成”应淡入，标题、日期、时间同时变灰；取消后恢复。点击标志区域仍打开详情，卡片高度不变；放大字体、横屏及亮暗主题下保持可读，不遮挡标题、日期与按钮。
5. 点击新建日程：浮层约半屏且与按钮等宽，显示“本地”；发送显示 AI 处理状态，校验保存后展示卡片并更新日期，含糊信息显示追问。输入、关闭、恢复和清空遵循下方专项验收。关闭后仍可操作日期和已有真实卡片。
6. 在日程页点击菜单或从左边缘拉开侧栏，分别通过遮罩、左滑和系统返回关闭；检查连续开关、拖动中断及返回手势取消时平滑恢复。
7. 切换深色模式、放大系统字体、旋转屏幕、切到后台再回来：主要内容可读可点，卡片日期／时间完整，底部按钮不被系统栏遮挡，浮层与输入区可滚动。

## 自然语言创建专项验收

1. 在设置 → 模型与 API 确认语言模型、接口和 API Key 已保存。打开新建日程，发送“明天下午4点开会，提前30分钟、10分钟和准点提醒”。处理期间显示 AI 状态，完成后回复中应包含 16:00 与三次提醒配置，标题不超过30个字符；弹窗显示可点开的日程卡片，背景页面切到明天且有圆点。新卡片无生成封面时显示日历占位，暂不实际响铃。
2. 点击卡片打开详情，检查日期、时间与文字；关闭后完成／恢复任务，排序和灰色状态仍正确。从最近任务划掉应用再打开，切到任务日期，数据与状态应保留；断网时仍可查看和完成任务。
3. 再点新建日程，应该是新的空会话；发送“今天买土豆、猕猴桃”，应创建一张当天的仅日期卡片，没有时间及闹钟。继续发送“再加茄子、辣椒”，应更新同一张卡片的详情，物品齐全且不出现第二项任务。从详情“继续会话”能看到全部文字。
4. 新建“明天下午提醒我开会”，应追问具体时间，不能先创建一张猜测时间的卡片。关闭再打开、重启后重新进入，都保留追问与消息；回答“下午5点”后只创建一张 17:00 卡片。发送只有“4点”等含糊描述时也应先澄清。
5. 新建“30s后提醒我喝水”，应提示改为分钟级，不新建任务；改为“5分钟后提醒我喝水”后可创建。新建“从明天起每天晚上8点喂猫，提前10分钟和准点提醒”，查看明天和后天都有独立卡片；完成其中一天不影响另一天，两天详情的“继续会话”打开相同历史。
6. 断网发送新任务，等待失败提示后恢复网络，点击“重试解析”：原用户消息只保留一份，成功后只建一张卡片。断网失败后重启应保留待处理消息，重新进入不自动发起调用。Key 未配置或无效时显示对应设置／鉴权提示，不显示保存成功。
7. AI 处理中关闭弹窗，稍后返回应能看到最终保存的任务。处理中在输入框准备下一段文字，前一轮完成后新输入不能被清空。尚未创建任务时点击顶部“清空”，旧会话及在途结果不能稍后复活；已创建任务的会话不再显示“清空”。
8. 在亮暗主题、大字体及横屏下检查处理状态、追问、失败提示、重试、卡片和键盘；关闭、返回、切换日期及侧栏过渡仍应连贯。多项不同时间的活动应引导分别新建，聊天查询应引导查看详情；周期单次编辑、仅本次删除和整个周期删除应按明确范围执行。

## 补充编辑删除专项验收

1. 新建“明天下午4点开会，提前30分钟、10分钟和准点提醒”，在同一会话中说“改成五点”。应仍为同一张卡片，时间改为17:00，标题、详情、明天的日期和三次提醒保持不变。再说“改到后天”，应只改日期，原日期圆点随真实计数更新。
2. 新建“今天买土豆、猕猴桃”，继续“茄子、酱油、辣椒”：应全部追加到同一采购详情，标题和日期保持原值。说“把土豆从清单里删掉”应只编辑清单，不删除任务；“不要删除这个日程”也不能触发删除。
3. 在普通任务会话中明确说“删除这个日程”，应直接删除，不出现确认弹窗；任务卡片消失，浮层关闭并提示已删除。再次新建是空会话，重启后原任务和会话不再出现。删除整项任务会清理其历史，测试时使用本次新建的测试任务。
4. 建立“从明天起每天18点喂猫，提前30分钟和准点提醒”，打开后天那张详情进入会话，说“只把本次改成19点，提前15分钟和准点提醒”。应只改后天；明天及其他日期仍为18点和原提醒。完成后天再恢复，仍保持19点及15分钟提前量，重启也保留。
5. 在周期会话只说“改成20点”应追问范围。答“从今天起及之后”，未完成的未来卡片应改为20点，已完成／过去记录不变；单次特殊备注和未提出改动的提醒配置继续保留。
6. 在周期会话说“删除这个日程”应询问本次还是整个周期。明确“仅本次”后，该次卡片及提醒消失，其他日期保留；连续切换日期及重启不能重新生成被删那次。再从另一日期说“删除整个周期”，全部日期卡片及共用会话都应消失。
7. 断网打开普通任务详情，点击“删除”，确认后完成本地删除，取消则保留；周期详情先选范围，再确认执行。检查亮暗主题、大字体、纵向滚动、展开收起及关闭动画，失败时保留内容并可重试。
8. 升级后检查已有任务、草稿和模型 Key 仍可用。编辑后重启，日期／时间／详情保留；删除后立即重新新建、快速切换页面，不能恢复被删会话或因陈旧草稿导致无法新建。

## 周期日程专项验收（0.9.0）

1. 新建“从明天起每天18点喂猫，提前30分钟和准点提醒”。分别查看明天、后天及更远日期：各日出现一张卡片，带循环图标；详情显示“每天”，不同日期共用聊天历史和封面。完成后天，仅后天变灰并排到已完成组，明天不变。
2. 从后天的详情进入会话，顶部“本次”与对话中的卡片都应为后天。说“只把本次改成19点，提前15分钟和准点提醒”：仅后天改变，其他日期维持18点。后天完成后再恢复、重启应用，应保留19点及独立提前量。
3. 从后天进入会话说“从本次起，后续都改为20点”：明天保持18点，后天及之后未完成记录变为20点，已完成记录保留。回复应明确起始日期。再从较远日期进入，说“从明天起全部改为21点”，应按明确的明天作为起点，不能默认从所选较远日期开始。
4. 仅说“改成17点”时应追问范围；回答“只改本次”后只影响选中的那次。旋转屏幕、关闭再从同一卡片进入后，本次日期及历史保持正确。单次改到另一日期后，原日期不应重新生成同一张卡片。
5. 分别创建“从明天起每周一和周四18点运动”“从2027年1月31日起每月31日复盘，到2027年3月31日结束”“从明天起每3天整理一次”。核对星期、2月跳过31日、结束日期包含当天及间隔天数。对间隔任务只改后续时间，原有每3天的日期不变。
6. 使用另一项测试周期，先保留一条过去记录和一条已完成记录。在会话说“停止整个周期”：今天及之后未完成卡片消失，过去及已完成记录和聊天保留。断网浏览更远日期、重启后再看，不能恢复未来卡片；保留卡片详情显示“已停止重复”。
7. 断网从周期详情点击“停止整个周期”，应本地生效；对保留的已完成卡片恢复完成状态，仍不能重新启用周期提醒。随后从历史卡片选择“删除整个周期”，确认后全部卡片及会话一起删除；取消则保留。

## 系统日历提醒

- 在「设置 → 通知提醒 → 系统日历」授权后，准点和提前提醒自动登记到专用本机日历「mebot 到点提醒」。仅日期日程和未配置提醒的日程只保存在 mebot。
- 日程及发生记录以 Room 为准。每次发生写入一条普通日历事件，标题和正文分别写入标题和备注。开始时间沿用日程时间，结束时间为开始后 5 分钟，重复设为仅一次。每个提醒各写入一条分钟偏移，`0` 代表日程发生时。
- 日程编辑、完成、删除及周期变更后，重新核对未来的日历提醒。重复登记复用同一日历事件，失败时设置页提供重试。周期日程沿用现有滚动展开范围，已写入的提醒由日历独立调度。
- OPPO Find X10 上手动开启日历响铃后，`Events.force_reminder` 从 `0` 变为 `1`。日历提供此字段时，mebot 为自己写入且仍有待触发提醒的事件设为 `1`，并读回确认。设备未提供该字段或写入未获确认时，保留普通日历提醒并显示响铃状态。
- 「验证日历响铃」创建一条约两分钟后提醒的日程，可直接打开系统日历详情。响铃开关写入结果与实际响铃分别验收。
